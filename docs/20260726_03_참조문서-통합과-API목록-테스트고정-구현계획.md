# 참조 문서 통합과 API 목록 테스트 고정 구현계획

관련 백로그: `BL-0726-01`

## 배경

`docs/development.md`(238줄)와 `docs/crawling_logic.md`(160줄)는 서술 범위가 겹쳐, 한 플랫폼을 이해하려면 두 문서를 오가야 한다. 여기에 `README.md`(292줄)까지 더해 3중 중복이 존재한다.

착수 전 코드·실데이터 대조 결과, **백로그에 기재된 근거 자체에 오류가 있음**을 확인했다. 통합을 먼저 수행하면 틀린 서술을 그대로 옮기게 되므로, 사실 정정을 선행한다.

### 실측 근거

`total_full_20260726.json` (1,868건) 기준 `platform_sequence_id` 보유율:

| 플랫폼 | 건수 | 보유 | 보유율 |
| --- | --- | --- | --- |
| linkedin | 631 | 631 | 100% |
| threads | 1,142 | 1,142 | 100% |
| x | 95 | 95 | 100% |

코드도 일치한다. `total_scrap.py:523-529`가 3개 플랫폼 모두에 `platform_sequence_id`를 부여한다.

```python
for p in linkedin_posts:
    p['sns_platform'] = 'linkedin'
    p['platform_sequence_id'] = p.get('sequence_id', 0)
```

즉 백로그의 "LinkedIn 630건 중 보유 0건" 주장과 `crawling_logic.md:81`의 "LinkedIn은 이 필드를 생성하지 않으며"는 **둘 다 사실과 다르다**.

실제 문제는 다른 지점이다. 필드는 100% 채워지지만 **LinkedIn의 값은 화면 순서를 반영하지 않는다**. `development.md:127-135`가 실측으로 입증했듯 Voyager 응답 배열 순서 자체가 저장글 화면 순서와 무관하기 때문이다. 따라서 정정 방향은 "필드 없음"이 아니라 "필드는 있으나 LinkedIn 값은 의미 없는 순서값"이다.

### API 목록 격차 실측

`/api/auth/*` 3종은 `BL-0505-03`이 지목한 죽은 코드다. 문서에 "미사용" 명시가 없어 누락인지 의도적 생략인지 구분되지 않는 상태다.

## Phase 3 — API 목록 테스트 고정

### Step 3-1. `tests/contract/test_api_surface.py` 신설

`tests/conftest.py:9-13`의 `app` fixture가 이미 존재하므로 재사용한다. `app.url_map`으로 라우트를 추출하는 방식이 동작함을 사전 확인했다 (17개 반환).

테스트 3종을 둔다.

1. **문서 누락 감지** — 코드 라우트가 `docs/architecture.md`에 전부 기재됐는지
2. **문서 유령 항목 감지** — 문서에만 있고 코드에 없는 라우트가 없는지
3. **라우트 총수 고정** — 라우트 증감 시 문서 갱신을 강제

```python
"""API surface가 문서와 일치하는지 검증한다.

라우트를 추가·삭제하면 docs/architecture.md도 함께 고쳐야 한다.
이 테스트가 실패하면 코드가 아니라 문서를 먼저 확인할 것.
"""
import os
import re

import pytest

_REPO_ROOT = os.path.dirname(os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
DOC_PATH = os.path.join(_REPO_ROOT, "docs", "architecture.md")
EXPECTED_ROUTE_COUNT = 17


def _code_routes(app):
    return {
        rule.rule
        for rule in app.url_map.iter_rules()
        if rule.rule.startswith("/api/")
    }


def _doc_routes():
    """백틱으로 감싼 코드 표기만 라우트로 인정한다.

    산문 중 /api/auth/* 같은 와일드카드 언급을 오탐하지 않기 위함이다.
    """
    with open(DOC_PATH, encoding="utf-8") as f:
        text = f.read()
    found = re.findall(
        r"`(?:GET|POST|PUT|DELETE)?\s*(/api/[A-Za-z0-9/<>:_-]+)`", text
    )
    return {m for m in found if not m.endswith("/")}


def _normalize(route):
    """/api/post/<int:sequence_id> → /api/post/"""
    return route.split("<")[0]


def test_all_code_routes_documented(app):
    code = {_normalize(r) for r in _code_routes(app)}
    doc = {_normalize(r) for r in _doc_routes()}
    missing = sorted(code - doc)
    assert not missing, (
        f"코드에 있으나 {DOC_PATH}에 없는 라우트: {missing}"
    )


def test_no_phantom_routes_in_doc(app):
    code = {_normalize(r) for r in _code_routes(app)}
    doc = {_normalize(r) for r in _doc_routes()}
    phantom = sorted(doc - code)
    assert not phantom, (
        f"{DOC_PATH}에 있으나 코드에 없는 라우트: {phantom}"
    )


def test_route_count_is_pinned(app):
    actual = len(_code_routes(app))
    assert actual == EXPECTED_ROUTE_COUNT, (
        f"API 라우트 수가 {EXPECTED_ROUTE_COUNT} → {actual}로 변경됐습니다. "
        f"{DOC_PATH}를 갱신하고 EXPECTED_ROUTE_COUNT도 함께 고치세요."
    )
```

설계 판단:

- **`_normalize()`로 path parameter를 제거**한다. 문서는 `/api/post/<sequence_id>`, 코드는 `/api/post/<int:sequence_id>`로 표기가 달라 원문 비교 시 오탐이 난다.
- **`_doc_routes()`는 백틱 코드 표기만 인정**한다. 단순 정규식(`/api/[...]+`)을 쓰면 Step 1-2가 문서에 넣도록 지시한 `/api/auth/*` 와일드카드 산문이 `/api/auth/`로 잡혀 phantom 테스트가 오탐한다. 실측 확인: 원안 정규식은 `위 3종은 /api/auth/* 로...`에서 `['/api/auth/']`를 반환한다. 백틱 한정 + 슬래시 종료 배제로 차단한다.
- **`DOC_PATH`를 `__file__` 기준 절대경로로 고정**한다. 상대경로는 실행 위치에 종속돼 `tests/` 하위에서 실행 시 `FileNotFoundError`가 난다. `tests/conftest.py:5`가 이미 같은 패턴을 쓴다.
- **총수 고정 테스트를 별도로 둔다**. 1·2번만으로는 라우트 추가와 문서 추가를 동시에 잊으면 통과해 버린다.
- `/` 와 `/<path:path>`는 정적 파일 서빙이므로 대상에서 제외한다.

**완료 기준**: 3개 테스트가 레포 루트와 `tests/` 하위 **어디에서 실행해도** 동일하게 통과한다.
