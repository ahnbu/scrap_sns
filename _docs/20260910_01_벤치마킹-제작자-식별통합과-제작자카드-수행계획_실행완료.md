## 1. 상황 (Situation)

### 1.1 사용자가 제기한 것

뷰어에서 **벤치마킹 → 이승필**을 골랐더니 7건만 나왔다. 사용자는 "그 사람이 쓴 모든 글이 떠야 하는 것 아닌가"라고 물었고, 원인을 "저장·MY·벤치마킹이 서로 배제하는 구조 탓"으로 추정했다. 함께 제기된 것이 둘 더 있다.

- 벤치마킹 대상 다수가 실제로는 여러 채널을 운영하는데 그 채널들이 계정 정보에 반영돼 있지 않다.
- 자료수집의 제작자 프로필(예: `강슬기.md`)에 링크드인·유튜브가 비어 있다. 스레드 프로필만 방문해도 알 수 있는 정보인데 왜 누락되나.

그리고 새 요구가 하나 붙었다. **뷰어 카드의 이름 옆에 프로필 아이콘을 두고, 그 사람의 프로필과 게시글(SNS·파일·URL)을 한눈에 보고 싶다** — 자료수집의 제작자별 프로필처럼.

## 3. 검토한 옵션과 기각 근거

### 3.1 채널 자동보강 — 기각

사용자 가설은 "스레드 프로필만 들어가도 확인 가능한 정보"였다. 세 경로를 실측했다.

| 경로 | 실측 | 판정 |
|---|---|---|
| 보유 데이터 내 이름 매칭으로 크로스 플랫폼 연결 | 활성 19계정 중 후보가 나온 건 1건(CHOI), 전부 동성이인 오탐(Seolhun/Jongwon/Soyeong Choi, Jay Choi) | 불가 |
| 스레드 프로필 직접 파싱 | `@marketer.ai.seulki` · `@gptaku_ai` 2건 스크랩 — 바이오·팔로워 수·인스타 링크·바이오 링크 1개는 나오나 **유튜브·링크드인 주소는 미노출** | 불가 |
| 바이오 허브 링크 1단계 추적 | `experience.ai.kr` 스크랩 결과 얻은 것은 favicon URL 2개(`domain=www.youtube.com`, `domain=marketerseulki.substack.com`). 실제 채널 주소는 JS 렌더라 정적 스크랩에 안 잡힘 | 도메인만, 핸들 못 얻음 |

한 사람이 플랫폼마다 다른 이름을 쓰고(한글 본명 / 영문 / 브랜드명), 링크드인은 저자가 내부 ID라 단서가 표시명뿐이다. 자동 연결은 구조적으로 오탐이 나며, **오탐 비용은 남의 글이 벤치마킹 목록에 섞이는 것**이다.

**수작업을 남기는 근거**(자동 처리로 대체 불가한 이유):
1. 위 세 경로가 실측으로 막혔다.
2. 대상이 활성 19계정으로 유한하고 1회성이다.
3. **입력 UI가 이미 구현돼 있다** — [script.js:4218](../web_viewer/script.js) `benchmarkDetailHtml()`이 플랫폼별 주소 입력란과 「주소 확인」 버튼을 렌더한다. 새로 만들 것이 없다.

따라서 자동화 대신 **결측 가시화**(W2-3)만 넣는다.

### 3.2 소급 표식을 어디에 쓸 것인가 — 1회성 백필 기각

| 안 | 내용 | 판정 |
|---|---|---|
| A. 1회성 백필 스크립트로 `total_full_*.json` 수정 | 가장 빠름 | **기각.** `merge_results()`는 upstream 8개 파일을 매번 다시 읽어 통합본을 재생성한다([total_scrap.py:660](../total_scrap.py)). 통합본에 직접 쓴 표식은 다음 수집에서 소멸한다 |
| B. upstream 플랫폼 파일까지 함께 수정 | 지속됨 | 기각. 파일이 8종이고 수집기마다 스키마 차이가 있어 유지 비용이 크다 |
| **C. `merge_results()` 정규화 단계에 「표식 재계산」을 항구 단계로 추가** | 매 실행마다 최신 계정 정보 기준으로 다시 붙는다 | **채택.** 계정을 새로 켜거나 채널을 추가하면 다음 수집에서 자동 반영된다 |

C는 기존 `_absorb_benchmark_mark()`(중복 병합 시 표식 합치기, [total_scrap.py:820](../total_scrap.py))와 같은 층에 놓인다.

### 3.3 제작자 카드 범위 — B안 채택

| 안 | 카드에 담기는 것 | 새로 필요한 것 | 판정 |
|---|---|---|---|
| A | 계정 정보(채널 배지·목적·그룹) + 그 사람 글 전체 | 카드 UI만 | 요구를 절반만 충족 |
| **B** | A + 제작자 프로필 요약(정체성·활동·전문분야) + 「자료수집에서 열기」(`obsidian://`) | 서버 API 1개 + 카드 UI | **채택** |
| C | B + 수집한 파일·URL 자료 목록을 뷰어 안에 재현 | 노트 인덱스 구축·동기화 | 기각. 옵시디언 `dataviewjs`가 이미 하고 있고, 그 목록은 파일을 여는 것이 목적이라 어차피 옵시디언으로 넘어간다 |

B의 그림: **SNS 글은 뷰어에서, 파일·문서는 옵시디언에서, 둘을 한 카드에서 오간다.**

### 3.4 P-2를 `username` 교체로 풀어도 되는가 — 안전 확인됨

`post_key`는 `platform:platform_id`로 만들어지며 `username`을 쓰지 않는다([utils/post_meta.py:93](../utils/post_meta.py) `build_post_key()`). 별표·숨김·메모는 `post_key` 기준으로 `sns_user_metadata.json`에 저장되므로 **`username`을 바꿔도 사용자 상태는 깨지지 않는다.**

## 4. 해결 (Resolution)

### 실행 웨이브

**순차 실행이다. 병렬·서브에이전트 실행이 아니며 웨이브를 겹쳐 돌리지 않는다.**

| 1 | W1 | 없음 | 표식·매칭 키가 맞아야 이후 판정이 의미를 가진다 |
