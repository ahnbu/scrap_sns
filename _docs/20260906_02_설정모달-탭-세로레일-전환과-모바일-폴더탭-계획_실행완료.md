## 1. 상황 (Situation)

설정(Settings) 모달은 탭 5개로 구성된다 — 태그 관리 / 숨김 관리 / 표시 / 벤치마킹 / 전체 크롤링.
현재 구현은 **밑줄 탭(underline tab)** 방식이다. 선택된 탭 아래에 보라색 2px 선이 그어지고, 나머지는 회색 글자로만 남는다.

## 2. 문제 (Complication)

### P1. 비활성 탭이 "누를 수 있는 것"으로 안 읽힌다 — 사용자 제보의 본체

- 비활성 탭 대비 **2.06:1**. WCAG AA 본문 기준 4.5:1의 절반도 안 된다.
- 원인은 색 하나가 아니라 **이중 감쇠**다. `text-gray-500`(`#6B7280`) 위에 `style.css:710`의 `opacity: 0.6`이 한 번 더 곱해진다. 회색만 썼다면 3.5:1은 나왔다.
- 활성/비활성 대비가 8배 차이라, 비활성 탭이 "꺼진(disabled) 라벨"로 보인다.
- 클릭 가능 신호가 **활성 탭의 밑줄 하나뿐**이다. 비활성 탭에는 배경·테두리·밑줄이 전부 없다.

### P2. 탭 바가 아래 본문과 따로 논다 — 사용자 제보 2차

- 탭 바와 본문을 가르는 선이 `border-white/5`(불투명도 5%)뿐이라 영역 경계가 안 보인다.
- 선택된 탭과 그 탭의 내용이 시각적으로 연결되지 않는다. 탭이 본문 위에 얹힌 별개 띠로 보인다.

### P3. 탭 너비가 들쑥날쑥하다 — 사용자 제보 3차

- 좌우 패딩이 0이고 `gap-3`만 있어 탭 폭이 글자 수에 그대로 좌우된다 (데스크톱 67 / 67 / 32 / 64 / 83px).
- 「표시」가 32px로 유독 좁아 리듬이 깨진다.

### P4. 모바일에서 탭 글자가 세로로 쌓인다 — 기존 결함, 제보에는 없었으나 실측으로 발견

- `index.html:507·513`(숨김 관리·표시)과 `501`(태그 관리)에 `whitespace-nowrap`이 없다. `519·527`(벤치마킹·전체 크롤링)에만 붙어 있다.
- 375/393px에서 앞 3개 탭의 폭이 16–26px = **글자 한 개 폭**. 글자가 세로로 쌓여 탭 높이가 38px → **110px**로 부풀고, 그만큼 본문 영역이 잘린다.
- `_docs/20260906_01` (P7)에서 `overflow-x-auto`를 넣어 "잘려서 못 누르는" 문제는 막았지만, 줄바꿈 자체는 남아 있었다.

### P5. 접근성 마크업이 없다

- `role="tablist"` / `role="tab"` / `aria-selected` / `role="tabpanel"`이 전부 없다. 화면 낭독기에서 탭 묶음으로 읽히지 않는다.

## 3. 검토한 옵션과 기각 근거

사용자와 미리보기 위젯으로 5개 안을 놓고 좁혔다.

| 안 | 내용 | 판정 |
|---|---|---|
| A-1 알약 세그먼트 | 어두운 트랙 위 알약 5개, 균등 분할 | **기각** — 사방이 막힌 도형이라 아래 본문과 이어지는 신호가 없다. P2 미해결 (사용자 지적) |
| B 밑줄 강화 | 현재 구조 유지 + 색·패딩·hover 보강 | **기각** — 정지 화면에서 비활성 탭이 여전히 "글자"다. P1이 hover 해야만 풀린다 (사용자 지적) |
| C 폴더 탭 한 벌 | 가로 폴더 탭, 전 폭 동일 | **보류(모바일용으로 채택)** — 구현 한 벌로 끝나지만, 이음이 선택된 탭 한 칸에서만 생겨 D보다 약하다 |
| D + 아이콘 레일 (대응①) | 데스크톱 세로 레일, 모바일은 레일 56px 아이콘만 | **기각** — 설정은 자주 여는 화면이 아니라 아이콘 의미를 학습할 기회가 없다. 「표시」/「벤치마킹」/「숨김 관리」를 아이콘만으로 구분해야 한다 |
| **D + 가로 폴더 탭 (대응②)** | 데스크톱 세로 레일, 640px 미만은 C의 가로 폴더 탭 | **채택** |

### 대응②를 고른 근거

- **D 그대로는 모바일에서 못 쓴다.** 본문 가용폭 309px − 레일 152px = **157px**. 태그 관리 탭의 `검색창 + 「+ 태그」 + 「일괄 적용」` 한 줄이 3줄로 무너진다.
- 640px을 경계로 잡으면 실측상 모달이 576px가 되어, 레일 152px를 빼도 본문이 **422px** 남는다. Tailwind `sm:` 브레이크포인트와 정확히 일치해 커스텀 브레이크포인트가 필요 없다.
- 대가는 레이아웃 두 벌 관리다. 이를 **DOM 한 벌 + CSS 전환**으로 묶어 완화한다 (아래 D1 원칙).

### 대가로 받아들이는 것

- 데스크톱에서 본문 폭이 670px → 약 518px로 줄어든다. 태그 관리 탭의 태그 목록 행이 좁아진다. 실제 표시는 검증 단계에서 화면으로 확인한다.
- 탭 모양이 폭에 따라 달라져, 이후 탭을 추가할 때 두 배치를 모두 확인해야 한다.

## 4. 해결 (Resolution)

### 설계 원칙

- **D1. DOM은 한 벌만 둔다.** `.tab-btn` 버튼을 데스크톱용·모바일용으로 복제하지 않는다. 복제하면 `document.querySelectorAll('.tab-btn')`이 5개 → 10개가 되어 아래 5개 검증 스크립트가 전부 오작동한다.
  - `scripts/verify_benchmark_viewer_headless.mjs` (3곳)
  - `scripts/verify_benchmark_scenarios.mjs` (2곳)
  - `scripts/verify_benchmark_ui_design.mjs` (3곳 + `parentElement`로 탭 바를 잡는 D1 검사)
  - `scripts/verify_benchmark_handle_check.mjs` (1곳)
  - `scripts/verify_benchmark_settings_headless.mjs` (2곳)
- **D2. `.tab-btn` 클래스명과 `data-target` 속성은 그대로 둔다.** 위 스크립트와 `tests/e2e/test_my_posts_filter_ui.py:373`, `tests/integration/test_server_routes.py:29`가 이 두 가지에 의존한다.
- **D3. 상태 표현을 CSS로 옮긴다.** 지금은 `switchTab()`이 Tailwind 유틸리티 클래스(`border-primary`, `text-gray-500` 등)를 직접 붙였다 뗀다. 배치가 두 벌이 되면 이 방식이 감당이 안 된다. JS는 `.active`와 `aria-selected`만 토글하고, 나머지는 `style.css`가 결정한다.
- **D4. 색은 팔레트 안에서 고른다.** `verify_benchmark_ui_design.mjs`의 D2 검사(`기존 팔레트 밖의 값이 없다`)는 `.tab-pane` 내부만 훑으므로 탭 바 restyle은 걸리지 않는다. 그래도 신규 색은 최소로 유지한다 — 비활성 글자색 1개(`#9BA1AC`)와 레일 배경 1개(`#16161B`)만 추가한다.
- **D5. 보라 강조색은 리터럴 `#7f0df2`로 쓴다.** 이 프로젝트에는 `--accent`도 `:root`도 없다 — `style.css`·`tailwind-built.css`·`index.html` 전체에서 CSS 변수 선언이 0건이고, 기존 코드는 리터럴을 직접 쓴다(`style.css:92·217·357·540·680·724`). `var(--accent)`를 쓰면 fallback이 없어 그 `box-shadow` 선언이 통째로 무효가 되고 활성 탭 강조선이 아예 안 그려진다.

## 5. 작업 단계

### T1 — 마크업 재구성 (`index.html`)

1. `471`의 모달 패널 안, 헤더(`480` 근처) 아래에 **본문 래퍼**를 새로 넣는다.
   ```
   <div class="settings-body flex-1 min-h-0 overflow-hidden">
     <div class="settings-tabs" role="tablist">
       <!-- 기존 index.html:500-531 의 .tab-btn 5개를 순서 그대로 옮긴다:
            tabTags / tabHidden / tabDisplay / tabBenchmark / tabMaintenance -->
     </div>
     <div class="settings-panes">
       <!-- 기존 index.html:535-731 의 .tab-pane 5개를 순서 그대로 옮긴다:
            tabDisplay / tabTags / tabHidden / tabBenchmark / tabMaintenance
            (DOM 상의 실제 순서. 표시 순서는 탭 바가 정한다) -->
     </div>
   </div>
   ```
   - 래퍼에 `flex-1 min-h-0 overflow-hidden`을 준다. 모달이 `max-h-[85vh] overflow-hidden`이라 이게 없으면 내부 스크롤이 죽는다.
2. `.tab-btn` 5개에서 배치용 Tailwind 유틸리티(`pb-3`, `border-b-2`, `border-primary`, `border-transparent`, `text-gray-500`, `hover:text-gray-300`)를 걷어낸다. `tab-btn`, `active`, `data-target`, `whitespace-nowrap`은 남긴다.
3. **모든** 탭에 `whitespace-nowrap`을 붙인다 (P4 수정 — 현재 `501`·`507`·`513`에 없음).
4. 각 탭에 아이콘 `<span class="material-symbols-outlined tab-icon">`을 넣는다. 모바일에서는 CSS로 숨긴다. 아이콘은 이 프로젝트가 이미 쓰는 Material Symbols에서 고른다 — `sell`(태그) / `visibility_off`(숨김) / `grid_view`(표시) / `target`(벤치마킹) / `sync`(전체 크롤링).
5. `role="tab"`, `aria-selected`, `aria-controls`를 각 버튼에, `role="tabpanel"`과 `aria-labelledby`를 각 `.tab-pane`에 붙인다 (P5).
6. `.tab-pane` 5개의 기존 클래스 문자열은 그대로 유지한다 — 들여쓰기만 한 단 깊어진다 (T4의 테스트 수정 필요).

### T2 — 스타일 (`web_viewer/style.css` 707–727 교체)

1. `opacity: 0.6` 삭제 (P1 근본 원인).
2. `.settings-body` / `.settings-tabs` / `.settings-panes` / `.tab-btn` / `.tab-btn.active` / `.tab-icon` 규칙을 새로 쓴다.
3. 기본(모바일 우선)은 **가로 폴더 탭**. 아래가 적용할 실제 선언이다.
   ```css
   .settings-body  { display: flex; flex-direction: column; }
   .settings-panes { flex: 1 1 auto; min-height: 0; display: flex; flex-direction: column; }
   .settings-tabs  {
     display: flex; flex-direction: row; flex: 0 0 auto;
     gap: 2px; padding: 6px 8px 0; background: #16161B;
     overflow-x: auto; overflow-y: hidden;
   }
   .tab-btn {
     flex: 0 0 auto; display: flex; align-items: center; gap: 8px;
     min-height: 40px; padding: 10px 14px;
     border-radius: 9px 9px 0 0;
     color: #9BA1AC; font-size: 1rem; font-weight: 600;
     transition: background-color .2s, color .2s;
   }
   .tab-btn:hover { background: rgba(255,255,255,0.06); color: #fff; }
   .tab-btn.active {
     background: #1E1E24; color: #fff;
     /* 위 3px 보라 + 좌우 1px 헤어라인. 아래 변은 비워 본문과 잇는다. */
     box-shadow: inset 0 3px 0 #7f0df2,
                 inset 1px 0 0 rgba(255,255,255,0.08),
                 inset -1px 0 0 rgba(255,255,255,0.08);
   }
   .tab-icon { display: none; }
   ```
4. `@media (min-width: 640px)`에서 **세로 레일**로 전환. 아래가 적용할 실제 선언이다.
   ```css
   @media (min-width: 640px) {
     .settings-body { flex-direction: row; }
     .settings-tabs {
       flex-direction: column; flex: 0 0 152px;
       gap: 2px; padding: 12px 0 12px 8px;
       overflow-x: visible; overflow-y: auto;
     }
     .tab-btn {
       width: 100%; padding: 10px 12px;
       border-radius: 9px 0 0 9px; text-align: left;
     }
     .tab-btn.active {
       /* 왼쪽 3px 보라 + 위아래 1px 헤어라인. 오른쪽 변은 비워 본문과 잇는다. */
       box-shadow: inset 3px 0 0 #7f0df2,
                   inset 0 1px 0 rgba(255,255,255,0.08),
                   inset 0 -1px 0 rgba(255,255,255,0.08);
     }
     .tab-icon { display: inline-flex; font-size: 20px; }
   }
   ```
   - 레일 폭 152px 안에 아이콘 20px + gap 8px + 좌우 padding 24px = 52px를 뺀 **100px**이 라벨 몫이다. 가장 긴 「전체 크롤링」이 16px 글자 5자 = 약 80px이라 들어간다. 넘치면 `verify_benchmark_ui_design.mjs`의 D1(`scrollWidth ≤ clientWidth`)이 잡는다 — 그때는 `font-size`를 0.9rem으로 내리거나 레일을 168px로 넓힌다.
5. `.tab-btn[data-target="tabMaintenance"]`의 강조·hover 색만 붉은 계열로 덮어쓴다 — `box-shadow`의 `#7f0df2` 자리를 `#E24B4A`로 바꾼 같은 선언을 기본·미디어쿼리 양쪽에 둔다.
6. `.tab-btn.active::after`(기존 밑줄 + `box-shadow` 글로우) 규칙은 삭제한다.

### T3 — 상태 토글 (`web_viewer/script.js` 3917–3939)

1. `switchTab()`에서 `border-primary` / `text-white` / `border-transparent` / `text-gray-500` 조작을 걷어내고, `.active` 토글 + `btn.setAttribute('aria-selected', isTarget ? 'true' : 'false')`만 남긴다(`isTarget`은 `btn.dataset.target === targetId`).

### 계획과 달라진 것

- **S10 판정 기준을 고쳤다.** 처음 정의한 "세 요소의 `top`이 2px 이내"는 틀린 기준이었다. 툴바가 `items-center`라 높이가 다른 요소끼리 `top`이 어긋나는 것이 정상이다(실측: 검색창 38px / 버튼 50px → 6px 차이). 「한 줄」을 세로 구간 겹침 + 툴바 높이 ≤ 최대 요소 높이로 다시 정의했다.
- **`.tab-pane`의 들여쓰기를 바꾸지 않았다.** T1-6은 "들여쓰기만 한 단 깊어진다"고 예상했지만, 200행 재들여쓰기는 diff만 키우고 실익이 없어 여는 태그에 `role`·`aria-labelledby`만 더했다. T1-6의 요구("클래스 문자열 유지")는 그대로 지켰고, T4-1의 테스트 교체도 계획대로 했다.
