# 뷰어 서버 재시작이 브라우저 탭을 여는 문제 제거

## 1. 상황

세션 `931037b9`(링크드인 이미지 복구 작업) 도중, 에이전트가 뷰어 서버를 재시작할 때마다 브라우저 탭이 포그라운드로 떴다. 사용자가 작업 중이던 화면을 4회 빼앗겼고 결국 중단 요청이 들어왔다.

> 근데 자꾸 포그라운드로 탭을 띄우는데... 이거 진짜 필수적인 건가?? 사용자 작업 방해할 가치가 있나?

세션 전문에서 확인한 호출 지점은 4곳이다 — `cmd /c wscript sns_hub.vbs` 1회, PowerShell `wscript sns_hub.vbs` 3회.

## 2. 문제

### 2.1 직접 원인 — 규칙이 부작용 있는 명령을 정본으로 지정했다

`AGENTS.md`의 검증 규칙은 이렇게 쓰여 있었다.

> `scrap_sns_server.py`, `index.html`, `web_viewer/` 변경 후에는 `wscript sns_hub.vbs` 또는 `npm run view`로 5000번 서버를 재시작한 뒤 검증한다.

그런데 `sns_hub.vbs`는 세 가지를 한다.

| 단계 | 동작 | 규칙이 요구한 것인가 |
|---|---|---|
| 1 | `scripts/restart_viewer_server.ps1` 호출 (서버만 재시작, 창 없음) | ✅ 그렇다 |
| 2 | `_usage/log-usage.mjs` 사용량 기록 | 아니다 (무해) |
| 3 | `cmd /c start http://localhost:5000/` — **브라우저 탭 열기** | ❌ 아니다 |

규칙은 ①만 필요했는데 명령은 ③까지 실행한다. 에이전트는 규칙에 적힌 명령을 그대로 따랐을 뿐이므로, 이것은 판단 실수가 아니라 규칙의 결함이다.

### 2.2 탭 없는 경로가 이미 있었는데 규칙이 안 가리켰다

`scripts/restart_viewer_server.ps1`은 `sns_hub.vbs`가 내부에서 호출하는 바로 그 스크립트다. 5000번 포트를 점유한 `scrap_sns_server.py`만 종료하고(다른 프로세스면 `throw`), `-WindowStyle Hidden`으로 재시작한 뒤 `/api/status`와 `/api/get-tag-catalog`가 200 JSON을 낼 때까지 최대 12초 확인한다. 규칙이 요구하는 동작과 정확히 같고, 탭은 열지 않는다. 다만 이름 붙은 진입점이 없어 규칙이 이 스크립트를 직접 가리키기 어려웠다.

### 2.3 규칙이 "왜"가 아니라 "어떤 명령"으로 쓰여 있었다

규칙의 의도는 "낡은 서버로 검증하지 마라"인데 표현은 특정 런처 이름이었다. 부작용을 따져볼 여지가 문장 안에 없다.

### 2.4 같은 결함이 테스트 실패 안내에도 복제돼 있었다

`tests/e2e/`의 8개 UI 테스트는 서버가 없을 때 이렇게 안내했다.

> `wscript sns_hub.vbs` 또는 `npm run view` 로 서버를 먼저 띄우세요.

테스트가 실패할 때마다 탭 여는 런처를 권하는 문구가 14곳에 있었다. `BACKLOG.md`의 `BL-0901-01` 메모도 비슷하게 어긋나 있었다 — `python scrap_sns_server.py`를 백그라운드로 띄우라고 적었지만, 5000번 포트가 이미 점유돼 있으면 기동에 실패한다.

### 2.5 파이프라인은 원인이 아니다

`plan-check` 스킬은 이미 이 조항을 갖고 있고, 실제로 이번 계획을 1차 검수에서 지적해 육안 검증 4곳을 headless 스크립트로 교체시켰다.

> headless 실행이 명시됐는가 — 창이 뜨면 사용자 포커스를 뺏어 병행 작업이 끊긴다.

즉 one-stop 파이프라인은 정상 작동했다. 다만 그 조항은 "UI·브라우저 **검증**"에만 걸리고, 서버 재시작 같은 준비 동작은 대상 밖이다. `done-check` 쪽에는 headless·포커스 관련 조항이 아예 없다(grep 0건).

## 3. 해결

### 3.1 검토한 옵션

| 안 | 내용 | 판정 |
|---|---|---|
| **A** | 탭 없는 재시작 명령(`npm run restart`)을 만들고 규칙이 그것을 가리키게 한다 | **채택** |
| B | `done-check` 스킬에 포커스 점유 지적 조항 추가 | 기각 — 이번 사고(재시작 명령)는 못 잡고, 계획 단계에서 `plan-check`가 이미 잡는 것과 중복. 전역 스킬 글자는 매 세션 컨텍스트 비용이다 |
| C | `sns_hub.vbs`에서 탭 열기 제거 | 기각 — 이 런처의 존재 목적이 "서버 켜고 화면 열기"다. 사용자 진입점을 깨뜨린다. `scripts/validate_sns_hub_launcher.ps1:36`이 브라우저 실행 구문 존재를 강제하기도 한다 |
| D | 전역 규칙(`~/.claude/CLAUDE.md`)에 "포커스 뺏지 마라" 추가 | 기각 — `plan-check`가 이미 담고 있고, 프로젝트별 명령 지식은 전역에 담을 수 없다 |

A안을 고른 근거는 두 가지다. 첫째, 인과 사슬이 레포 안에서 완전히 닫힌다 — 규칙이 런처를 지정했고 런처가 탭을 열었다. 파이프라인을 고쳐도 "이 프로젝트에서 서버만 재시작하는 명령이 무엇인가"는 알 수 없다. 둘째, 「결정적 로직은 자연어 지시가 아니라 스크립트로 구현한다」는 기준상, "탭 열지 마라"를 규칙 문장으로 반복하는 것보다 **탭을 안 여는 명령에 이름을 붙이는 것**이 한 층 아래의 해법이다.

### 3.3 검토 과정에서 스스로 잡은 결함 2건

1. **`scripts/verify_*_headless.mjs` 글로브가 실제 headless 스크립트를 배제했다.** 규칙 초안에 이 패턴을 썼는데, 실제로 `hidden-browser-verify-runner.mjs`를 쓰는 검증 스크립트 7개 중 `verify_external_summary_icons.mjs`와 `verify_scrap_result_modal_layout.mjs`는 이름에 `headless`가 없다. 파일명 글로브 대신 러너 파일을 가리키도록 고쳤다 — 이름은 바뀌어도 러너는 durable identity다.
2. **`npm run stop`도 같은 계열의 함정이다.** `stop_viewer.bat`에는 `pause`가 두 번 있어 에이전트가 실행하면 응답을 기다리며 멈춘다. 규칙 목록에 경고를 붙였다.
