## 1. 상황 (Situation)

### 1.1 뷰어에는 성격이 다른 두 개의 장치가 있다

혼동을 막기 위해 먼저 구분한다. **이번 계획이 건드리는 것은 ①번뿐이다.**

| | 무엇인가 | 어디 있나 | 이번 범위 |
|---|---|---|---|
| **①** | `MY` 버튼 — 누르면 내가 쓴 글만 보여주는 필터 | 화면 맨 위 필터 줄 (`All ★ in @ X ▶` 옆) | **수정 대상** |
| **②** | 「목록에서 내 글 숨기기」 체크박스 — 평소 목록에 내 글을 섞을지 정함 (기본: 숨김) | 설정 창 > 「표시」 탭 | **손대지 않음** |

`MY` 버튼은 전등 스위치처럼 **누르면 켜지고 다시 누르면 꺼지는** 방식이다.
이 문서에서 「켜진다」는 사용자가 클릭해 눌린 상태가 되는 것, 「풀린다」는 그 상태가 해제되는 것을 뜻한다.

### 1.2 사용자가 보고한 이상 현상

1. **X 를 고르면 0건이 나온다.**
2. **내 글은 `MY` 를 누를 때만 보여야 하는데 `All` 을 눌러도 계속 나온다.**
3. **쓰레드를 누르면 내 글밖에 안 보인다.**

### 1.3 실측 데이터 (2026-08-27 20:04 기준)

⚠️ **아래 숫자를 테스트 단언에 상수로 박지 않는다.** 수집이 돌 때마다 바뀌므로 `/api/posts` 에서 파생시킨다.

- 통합 파일 `output_total/total_full_20260827.json` — 총 2,558건
  (Threads 1,304 / LinkedIn 699 / YouTube 460 / X 95)
- 내 글(`is_own_post: true`) 68건 — LinkedIn 36 + Threads 32. **X·YouTube 에는 0건이다.**
- 사용자 상태(`web_viewer/sns_user_metadata.json`) — 별표 8건, 숨김 3건. **셋 다 타인 글이다.**
- 내 글 68건 중 **본문이 같은 교차 게시가 23쌍**이다. 실제로 쓴 글은 45편이고,
  같은 글을 LinkedIn·Threads 양쪽에 올려 68건으로 세어진다. (T6 이 다룬다)
  - **짝 판정 신뢰도 실측**: 23쌍 **전부** LinkedIn 1건 + Threads 1건 조합이고, 쌍 내부 작성일 차이는 **전부 0일**이다.
    본문 앞 40자 정규화 기준으로 3건 이상 뭉치는 키는 **0개**이며, 앞 40자와 앞 60자가 같은 45편을 준다(안정 구간).

## 2. 문제 (Complication)

### 2.1 P1 — `MY` 버튼이 켜진 것을 화면이 알려주지 않는다 (근본 원인)

`script.js:325` 는 버튼이 켜질 때 `active` 클래스를 붙인다.

```javascript
myPostsBtn.classList.toggle('active', showOwnPostsOnly);
```

그런데 **`active` 를 스타일링하는 CSS 규칙은 세 개뿐**이고(`style.css` 전수 확인),
`MY` 버튼은 그중 어디에도 해당하지 않는다.

| CSS 규칙 | 적용 대상 | `MY` 버튼이 해당되나 |
|---|---|---|
| `.filter-chip.active` (`style.css:91`) | 플랫폼 칩 | ❌ `MY` 에는 `filter-chip` 클래스가 없다 (`index.html:152`) |
| `.global-tag-chip.active` (`style.css:536`) | 태그 칩 | ❌ |
| `.tab-btn.active` (`style.css:712`) | 설정 창 탭 | ❌ |

즉 `MY` 버튼은 **켠 상태와 끈 상태가 화면상 완전히 같다.** 색도 테두리도 글자 굵기도 변하지 않는다.
사용자는 필터가 걸려 있다는 사실 자체를 알 수 없다.

### 2.2 P2 — 그 보이지 않는 상태가 브라우저에 영구 저장된다

`script.js:332` 가 상태를 `localStorage` 에 쓴다. 한 번 켜면 **브라우저를 껐다 켜도 켜진 채로 남는다.**

### 2.3 P1 + P2 가 만드는 실제 경로 — 세 증상이 여기서 나온다

`MY` 가 켜진 동안 필터는 「플랫폼 AND 내 글」로 결합한다(`script.js:2173-2175`).
**2026-08-27 21:00 깨끗한 브라우저에서 클릭으로 재현한 실측이다.**

| 조작 | 상단 라벨 | 화면 | 대응 증상 |
|---|---|---|---|
| 초기(All) | `2487 / 2490 건` | 정상 | — |
| `MY` 클릭 | `68 / 2558 건` | 내 글만 | — |
| → `X` 클릭 | `0 / 2558 건` | **0건** | 증상 1 |
| → `YouTube` 클릭 | `0 / 2558 건` | **0건** | — |
| → `Threads` 클릭 | `32 / 2558 건` | **내 글 32건만** | 증상 3 |
| → `All` 클릭 | `68 / 2558 건` | **내 글 68건만** | 증상 2 |
| 저장값 확인 | `sns_own_posts_only: "true"` | **영구 보존** | — |

**세 증상이 모두 그대로 살아 있다.** 사용자가 지금 겪지 않는 것은 고쳐져서가 아니라
현재 쓰는 브라우저에 `MY` 가 꺼진 상태로 저장돼 있기 때문이다. 한 번 누르는 순간 다시 시작된다.

### 2.4 P3 — 카드 안에서 가로 구분선이 중복된다

카드 60장을 실측한 결과 **모든 카드에 가로선이 정확히 2개**씩 있다(메모가 있으면 3개).

| 위치 | 정의 위치 | 판단 |
|---|---|---|
| 지표 행 위 (`👁 797  ♡ 9  💬 2` 위) | `script.js:2936` `border-t border-white/5` | **불필요** |
| 메모 위 (메모 있을 때만) | `style.css:259` `border-top` | **불필요** |
| 푸터 위 (`+note / View Original` 위) | `script.js:3166` `border-t border-white/5` | 유지 |

**왜 불필요한가**: 카드가 이미 `gap: 12px` 로 모든 블록을 자동 분리한다(실측 확인).
선이 없어도 지표 행은 본문과 12px 떨어져 있다. 선은 그 위에 덧그은 것이다.

**일관성도 깨져 있다.** 지표 행에는 선이 있는데 바로 아래 태그 행에는 없다. 둘 다 「글에 딸린 정보」인데
하나만 선을 갖는다. 실측하니 지표선과 푸터선 사이는 **86px, 그 사이에 태그 한 줄뿐**이다.

## 3. 해결 방안 (Resolution)

### 3.1 옵션 비교 및 기각 근거

| 옵션 | 내용 | 기각 / 채택 근거 |
|---|---|---|
| **옵션 A (채택)** | `MY` 버튼은 그대로 두고 **동작만 고친다** — 켜지면 보이게, 플랫폼을 고르면 풀리게, 저장하지 않게 | 세 증상이 모두 사라진다. MY 오작동(T1~T3)만 놓고 보면 **고칠 테스트 3개**다(T4~T6 를 더해도 5개). 잃는 기능 없음 |
| **옵션 B** (이전 안) | `MY` 를 플랫폼 칩과 같은 **배타 탭으로 전환** | **기각.** 사용자가 겪는 결과는 옵션 A 와 같은데 **고칠 테스트가 18개**다. 그 18개는 직전 `_docs/20260827_03`·`04` 가 고친 **내 글 정렬을 지켜보는 안전망**이라, 통째로 다시 쓰면 정렬이 틀어져도 알아채지 못한다. 설정의 숨김 체크박스도 함께 없애야 해 범위가 더 번진다 |
| **옵션 C** | `MY` 클릭 시 플랫폼별 하위 필터 바 노출 | **기각.** 내 글이 68건뿐인데 UI 층만 늘어난다 |
| **옵션 D** | 아무것도 하지 않는다 | **기각.** 2.3 절대로 세 증상이 지금 재현된다. 게다가 원인이 화면에 드러나지 않아 사용자가 스스로 빠져나올 수 없다 |

**핵심 판단**: 이전 안은 원인을 「AND 결합이 오판이었다」로 봤다. 절반만 맞다.
AND 결합 자체는 죄가 없다 — "LinkedIn 중 내 글"은 쓸 만한 기능이다.
진짜 문제는 **AND 가 걸려 있다는 사실을 화면이 숨긴다**는 것이고, 그건 CSS 한 군데와 핸들러 몇 줄로 잡힌다.

### 3.2 상세 변경 계획

#### T1. `MY` 버튼이 켜지면 보라색으로 보이게 한다 (P1)

- **정본**: `index.html:152` 또는 `web_viewer/style.css`
- 플랫폼 칩이 켜졌을 때와 **같은 보라색**(`.filter-chip.active` 의 `#7F0DF2`)을 쓴다.
  같은 줄에 있는 버튼이 같은 방식으로 켜져 보여야 사용자가 규칙을 하나만 익힌다.
- **구현 주의**: `#myPostsBtn.active` 규칙을 새로 만드는 방식은 Tailwind 유틸리티와
  우선순위가 얽힐 수 있다. `MY` 버튼에 `filter-chip` 클래스를 **추가**해
  기존 `.filter-chip.active` 규칙을 그대로 타는 편이 안전하다.
  - ⚠️ 단, `filterContainer` 의 클릭 위임 핸들러(`script.js:303-318`)가 `.filter-chip` 을 잡는다.
    `MY` 에 `data-filter` 속성이 없으므로 `currentFilter` 가 `undefined` 가 되지 않도록
    핸들러에서 `MY` 를 먼저 걸러내거나, `data-filter` 대신 전용 분기를 둔다. **T2 와 함께 설계한다.**

#### T2. 플랫폼 버튼을 누르면 `MY` 가 저절로 풀리게 한다 (P1·P3의 증상)

- **정본**: `web_viewer/script.js:303-318` (필터 칩 클릭 위임 핸들러)
- 플랫폼 칩(`All`·`★`·`in`·`@`·`X`·`▶`)을 클릭하면 `showOwnPostsOnly = false` 로 되돌리고
  `MY` 버튼의 켜짐 표시도 함께 끈다.
- **근거**: 플랫폼을 골랐다는 건 그 플랫폼 글을 보겠다는 뜻이다. 내 글만 보는 상태를 유지할 이유가 없다.
  이 한 줄로 `X`→0건, `YouTube`→0건, `Threads`→내 글만, `All`→내 글만이 **동시에 사라진다.**
- 반대 방향(`MY` 를 누르면 플랫폼 선택을 `All` 로 되돌릴지)은 **바꾸지 않는다.**
  현재대로 두면 "쓰레드 보다가 `MY` 를 누르면 쓰레드 중 내 글"이 되는데, 이건 오작동이 아니라
  의도된 조합이고 `MY` 가 보라색으로 켜져 있으므로 사용자가 인지할 수 있다.

#### T3. `MY` 상태를 저장하지 않는다 (P2)

- **정본**: `web_viewer/script.js:86-95, 184, 330-336`
- `localStorage` 저장·복원을 제거한다. 뷰어를 열면 항상 전체 글부터 시작한다.
- 과거에 저장된 값이 남아 있으면 여전히 켜진 채로 시작하므로, 초기화 시 **한 번 지운다**:
  ```javascript
  localStorage.removeItem('sns_own_posts_only');
  ```
- ⚠️ `sns_hide_own_posts`(설정의 숨김 체크박스)는 **그대로 둔다.** 그건 ②번 장치이고 이번 범위가 아니다.

#### T4. 카드의 불필요한 가로선 2개를 제거한다 (P3)

- **정본**: `web_viewer/script.js:2936` — `metrics-row` 의 `border-t border-white/5` 제거
- **정본**: `web_viewer/style.css:259` — `.note-section, .note-editor` 의 `border-top` 제거
- **푸터 선은 남긴다.** 위쪽은 전부 「글에 대한 정보」(본문·이미지·지표·태그·메모)이고
  푸터만 「버튼」이다. 정보와 액션 사이에 선 하나면 충분하다.
- 이미지 테두리(`script.js:2955` `border border-white/5`)는 **남긴다.**
  그건 구분선이 아니라 이미지 액자다.
- `.metrics-row` **클래스명은 반드시 유지한다.** `tests/e2e/test_metric_layout_ui.py:23` 과
  `test_metric_as_of_ui.py:19` 가 이 클래스로 지표 행을 찾는다.

#### T5. 상단 건수 라벨에서 분모를 뺀다

- **정본**: `web_viewer/script.js:247-261` (`getPopulationTotal()`, `updateTotalPostsLabel()`)
- 지금은 `2487 / 2490 건` 처럼 뒷숫자(모집단)를 함께 보여준다. **뒷숫자를 없애고 보이는 건수만 표시한다.**
- **근거**: 분모 2,558은 플랫폼별 수집 건수를 단순 합산한 값이라 "내가 본 글이 몇 개냐"와 다르다.
  게다가 내 글 쪽은 교차 게시가 23쌍이라 중복 산정돼 있다(1.3 절). 부정확한 비율을 상시 노출하느니
  지금 화면에 몇 개가 걸렸는지만 말하는 편이 낫다.
- `getPopulationTotal()` 은 더 쓰이지 않으므로 **함께 제거한다.**

#### T6. 내 글 건수를 중복 제외해 표시한다

- **정본**: `web_viewer/script.js` — `updateTotalPostsLabel()` 및 내 글 집계 지점
- `MY` 가 켜진 동안 라벨을 `45편 · 68건` 형태로 표시한다.
  - **편** = 교차 게시를 하나로 친 실제 글 수
  - **건** = 화면에 있는 카드 수
- **카드는 합치지 않는다. 68장 그대로 보여준다.** 같은 글이라도 LinkedIn 과 Threads 의
  조회수·좋아요가 다르므로, 카드를 합치면 플랫폼별 성과 비교가 불가능해진다.
  사용자 지시는 「건수를 중복 제외로 반영」이지 「중복 카드를 숨겨라」가 아니다.
- **짝 판정 규칙** (1.3 절 실측으로 검증된 기준):
  ```
  같은 날 작성  AND  본문 앞 40자(한글·영숫자만 남긴 정규화) 동일  AND  플랫폼이 서로 다름
  ```
  세 조건을 **모두** 요구한다. 날짜 조건을 빼면 다른 시기에 쓴 비슷한 도입부가 잘못 묶일 수 있다.
- `MY` 가 꺼진 상태에서는 이 계산을 하지 않는다 — 타인 글에는 교차 게시 개념이 없다.
