# 유튜브 요약 파이프라인 재설계

## 목적

유튜브 저장 영상 수집은 [20260824_05 계획](../20260824_05_유튜브-저장영상-수집-반영-계획(실행완료).md)에 따라 2026-08-25 파일럿(drive7 81건)까지 실행 완료됐다. **기능은 동작하나 실사용에서 세 가지가 드러났다.**

| # | 드러난 문제 | 실측 |
|---|---|---|
| 1 | **돈 주고 만든 요약이 화면에 안 보인다** | 카드가 표시하는 앞 200자가 전부 제목·설명. 요약은 본문 1,125자 뒤에 붙어 0글자 노출 |
| 2 | **본문이 마케팅 광고로 채워져 있다** | 81건에 홍보 URL 243개·해시태그 511개. 검색 인덱스까지 오염 |
| 3 | **비용이 추정의 6배, 그중 절반은 낭비** | 파일럿 2,095원(추정 "수백 원"). 실제 필요 토큰의 **2.2배**가 청구됨 |

이 SPEC은 요약 파이프라인을 다시 설계하기 위한 **의사결정 앵커**다. 이 세션에서 확보한 실측 근거가 컨텍스트 압축으로 증발하는 것을 막는 것이 1차 목적이다.

## 요구사항

- **R1.** 카드 목록에서 영상 내용을 **읽지 않고도** 파악할 수 있어야 한다.
  - *why*: 저장 영상 아카이브의 존재 이유가 "그 영상 뭐였지"를 푸는 것이다. 현재는 광고문구만 보인다.
- **R2.** 자막에만 등장하는 내용(제품명·인물·핵심 주장)을 **검색으로 찾을 수 있어야** 한다.
  - *why*: 자막 전문은 검색 인덱스에서 제외하기로 이미 결정됐다(계획서 4.3). 요약이 유일한 대리물인데 현재 265자라 대리 역할을 못 한다.
- **R3.** 요약 생성 비용이 **실행 중에 보여야** 한다.
  - *why*: 현재 `usageMetadata`를 버려서 2.2배 낭비를 사후 역산으로만 알아냈다. 8/14 녹취 사고와 같은 구조다.
- **R4.** 신규 영상 수집이 **뷰어 업데이트 버튼을 오래 묶지 않아야** 한다.
  - *why*: `/api/run-scrap`은 동기 블로킹이다. 일상 수집은 신규 몇 건이라 문제없으나 전량 재처리가 끼면 무너진다.
- **R5.** 요약 형식을 바꿔도 **전량 재생성이 강제되지 않아야** 한다.
  - *why*: 파일럿에서 자막 정제 로직을 손댄 것이 낭비의 유력한 원인이다. 형식은 앞으로도 바뀐다.
- **R6.** 요약용 `agy` 호출이 **세션 대시보드를 오염시키지 않아야** 한다.
  - *why*: `agy --print` 1회당 세션 1건이 `sessions.db`에 기록된다. 448건이면 대시보드 기본 목록이 요약 호출로 덮인다. **오늘 테스트 호출들이 이미 `is_subtask=0`으로 올라와 있다**(F11).

## 결정안

### D1. 요약 생성 — agy `gemini-3.7-flash-medium`, 전량 자동

> 트레이드오프: API 대비 4배 느리지만(건당 16초) **0원이고 사실 정확도가 높다.** 일괄 처리가 예외적 상황이라 속도는 결정 요인이 아니다.

- 호출: `agy --model gemini-3.7-flash-medium --print="(agy) <프롬프트>"`
- **프롬프트 첫 줄 `(agy)` 필수** — `detectLeadingAiCliTag()`가 `ai_cli_tag:agy`로 판정해 `is_subtask=1`을 붙인다 (F11)
- 입력에 **제목·설명을 자막과 함께** 넣는다 — 고유명사 교정에 필수 (F5)
- **`--output-format json`으로 호출한다** — `usage`(입력·출력·사고·캐시 토큰)와 `status`를 함께 받아 R3를 충족한다 (F12)
- 캐시(`summaries/{videoId}.json`)는 유지. 재실행 시 재생성하지 않는다 (R5)

🔴 **캐시 키에 결함이 있다 — plan에서 반드시 고친다.**

현재 캐시는 `transcript_sha1` **하나만** 비교한다. 그래서 **프롬프트·출력 형식이 바뀌어도 캐시가 히트해 옛 형식이 그대로 재사용된다.** 이번 재설계는 형식이 통째로 바뀌므로 이 상태로는 81건이 갱신되지 않는다.

| 필요한 변경 | 이유 |
|---|---|
| 캐시 키에 **프롬프트 버전**을 추가 (`prompt_version` 또는 프롬프트 문자열의 해시) | 형식이 바뀌면 자동으로 캐시 미스 → 재생성 |
| 캐시 파일에 **`model`·`prompt_version`** 기록 | 어떤 형식으로 만든 요약인지 사후 판별 |

이 결함을 안 고치면 `--refresh-summaries` 강제 플래그에 매번 의존해야 하고, **그 플래그는 전량 재생성이라 부분 갱신이 불가능하다.**

### D2. 요약 층위 — 한 덩어리, 뷰어가 잘라 보여준다

> 트레이드오프: 상세까지 `full_text`에 넣어 스냅샷이 약 +1.1MB 늘지만, 그 대가로 **검색 인덱스와 신규 UI 0개**를 얻는다 (F8, F9).

`full_text` 구성 순서 — **요약이 맨 앞**이다.

```
<제목>

[요약] <한줄>

- <핵심 1>
- <핵심 2>
- <핵심 3>
- <핵심 4>

[상세]
<소주제 1>
<3~5문장>
 …
[설명]
<산문 설명 — URL·해시태그 제거>

[타임라인]
00:00 …
```

키워드 줄은 넣지 않는다 (A4).

- 카드는 기존 `line-clamp-4`로 **제목 + 한줄 + 핵심 앞부분**만 보인다 (C8)
- 「더보기」로 인라인 확장, 헤더 복사 버튼으로 전문 복사 — **모두 기존 기능**
- 마크다운 미사용 (C1)

### D3. 자막 재수집 — 타임스탬프 보존

> 트레이드오프: 76건 약 8분이 들지만 **비용 0**이고, 타임라인 없는 30%를 채우며 요약에 시각을 넣을 길이 열린다.

- 현재 `clean_vtt`가 `-->` 줄을 버려 시각이 0개다 (C4)
- 재수집 후 자막에 시각을 보존하고, 설명글에 타임스탬프 목차가 없는 30%는 자막에서 생성한다

🔴 **실행 순서가 강제된다 — 어기면 요약을 두 번 만든다.**

자막을 재수집하면 자막 본문이 바뀌므로 `transcript_sha1`이 **81건 전부 달라진다.** 요약을 먼저 만들면 그 요약이 통째로 무효가 되어 다시 만들어야 한다. **이것이 F2에서 확인한 2.2배 낭비와 정확히 같은 메커니즘이다.**

```
① 자막 재수집 (타임스탬프 보존)  →  ② 요약 생성  →  ③ 통합본 재생성
```

파일럿에서 이 순서를 어겨 자막 정제 로직을 나중에 고쳤고, 그래서 요약이 재생성됐다.

이 세션에서 **실행으로 확인한 것만** 적는다. 추정은 그렇게 표기한다.

### F1. 파일럿 실제 비용 — 2,095원, 추정의 6배

| 항목 | 값 |
|---|---:|
| 모델 | `gemini-3.7-flash` (프로젝트 `gen-lang-client-0014424498`, 8/25) |
| 입력 / 출력 토큰 | 1,870,406 / 10,824 |
| 단가 (Cloud Billing Catalog API, KRW) | 0.0010888 / 0.0054440 per token |
| **비용** | **2,095원** (76건 → 건당 27.6원) |

구현 세션 추정은 *"파일럿 수백 원 / 전량 477건 약 2천 원"* 이었다. 빗나간 원인은 자막 평균을 **10KB로 가정**했으나 실측 **21,785자(약 21KB)** 였던 것.

### F2. 🔴 청구가 실제 필요량의 2.22배 — 원인 미확정

| 항목 | 값 |
|---|---:|
| 자막 76건 실제 토큰 (`countTokens` 실측) | **842,580** |
| 실제 청구된 입력 토큰 | **1,870,406** |

### F13. agy 쿼터는 CLI로 조회된다 — `agy --print="/usage"`

> ⚠️ 초판에 *"CLI로 조회할 수 없다"* 고 적었으나 **틀렸다.** `--disable-slash-commands` 플래그가 print 모드에 적용된다는 것은 곧 **print 모드에서 슬래시 커맨드가 동작한다**는 뜻이었고, 실제로 동작한다.

```bash
agy --print="/usage"
```

출력 — 탭 구분, 리셋 시각은 ISO 8601 UTC:

```
Gemini Models	Weekly Limit Remaining	80%	2026-08-26T05:54:06Z
Gemini Models	Five Hour Limit Remaining	80%	2026-08-25T06:12:27Z
Claude and GPT models	Weekly Limit Remaining	90%	2026-08-29T06:24:44Z
Claude and GPT models	Five Hour Limit Remaining	96%	2026-08-25T08:41:23Z
```

`/quota` 는 `/usage` 의 별칭이다. 관련 커맨드: `/credits`(G1 크레딧 잔량·구매 링크), `/model`, `/effort`.

**🔑 쿼터가 두 계열로 분리돼 있다.** `Gemini Models` 와 `Claude and GPT models` 가 별도 한도다. agy **기본 모델이 Claude Sonnet 4.6**이므로, `--model gemini-3.7-flash-medium` 으로 요약을 돌리면 **Gemini 쿼터만** 쓴다.

**→ 측정 프로토콜이 성립한다 (실측 검증):** `/usage` 를 모델 지정 없이(기본 Claude) 호출하면 **Gemini 잔량은 변하지 않는다.** 2회 연속 호출에서 Gemini 80% 고정, Claude/GPT만 98%→96% 감소. 즉 **측정 도구가 측정 대상을 오염시키지 않는다.**

⚠️ 한계: 잔량이 **정수 `%`** 라 분해능이 1%p다. 건당 소모가 1%p 미만이면 여러 건을 돌려야 움직인다.

**2026-08-25 12:3x KST 앱 화면 실측 (동일 값):**

| 구분 | 잔량 | 갱신까지 |
|---|---:|---|
| Gemini Models — 주간 | **80%** | 1일 2시간 |
| Gemini Models — 5시간 | **81%** | 2시간 37분 |
| Claude·GPT — 주간 | 91% | 4일 2시간 |
| Claude·GPT — 5시간 | 100% | — |

**역산 (⚠️ 신뢰도 낮음)**: 세션 DB 기준 최근 7일 agy 세션 **15건**. 그 사이 주간 쿼터 20% 소모. 단순 나누면 건당 1.3%, 주간 한도 약 **75건**. 448건은 그 **6배**다.

이 역산의 한계 — 확정 근거로 쓸 수 없다:
- 15건 중 대화형 세션은 멀티턴이라 단발 요약보다 훨씬 무겁다
- 사용자가 Antigravity **앱**에서 한 작업도 같은 쿼터를 쓰는데 세션 DB에 안 잡힌다
- 화면의 `%`가 **요청 수 기준인지 토큰 기준인지 모른다**. 건당 34,000토큰(F12)인 요약 호출은 토큰 기준이면 일반 대화보다 무겁다

**→ A12는 유효하다.** 잔량이 넉넉한 것과 448건을 한 번에 감당하는 것은 다른 문제다.

### F15. 구분자 표기 4개 안 — 카드 미리보기 시뮬레이션

| **B** | `[요약] 한줄` / `- 항목` / `[상세]` | 무난 | ✅ **`-`가 마크다운 불릿로 살아남음** |

| D | `📌 한줄` / `· 항목` | 눈에 띄나 설명글에 이미 이모지(🚨🎙️✨)가 많아 변별력 낮음 | ❌ |

초판 권장은 A(기호)였으나 **B로 바꾼다.** 이 레포의 산출물은 SNS 글감·강의 자료로 재활용되므로(`_SNS/_docs/…Keep-글감목록…`), 복사한 텍스트가 마크다운으로 살아남는 쪽이 낫다.
