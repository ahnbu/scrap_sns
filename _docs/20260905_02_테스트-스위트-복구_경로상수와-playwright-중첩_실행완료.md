# 죽어 있던 테스트 스위트 복구 — 경로 상수와 Playwright 중첩 호출

## 1. 상황

X 게시일시 KST 백필 작업의 회귀 검증을 돌리다 두 가지가 걸렸다.

| 증상 | 최초 판단 |
|---|---|
| `pytest tests/contract` 2건이 항상 실패 | 폴더 개명 때 경로 상수만 안 고쳐진 것 |
| `pytest tests/smoke` 1건이 **단독은 통과, 함께 돌리면 실패** | asyncio 루프 잔존으로 인한 순서 의존 |

둘 다 X 작업과 무관해 그때는 고치지 않고 별도 과제로 남겼다.

## 2. 문제 — 파고 보니 하나는 진단이 틀렸고, 하나는 훨씬 컸다

### 2.1 contract: 진단대로였다

`tests/contract/test_api_surface.py:10` 이 `docs/architecture.md` 를 가리키는데 실제 경로는 `_docs/architecture.md` 다. 커밋 `e2edbef`("refactor(docs): docs/ → _docs/ 폴더명 통일")가 **같은 파일의 docstring(3줄)은 고쳤으면서 상수만 놓쳤다.** `docs/` 폴더가 아예 없어 `FileNotFoundError` 로 죽었다.

같은 개명에서 놓친 것이 하나 더 있었다 — `pytest.ini:6` 의 `norecursedirs = tmp docs old`. 현재는 `testpaths = tests` 라 영향이 없지만 존재하지 않는 폴더를 가리키는 죽은 설정이다.

### 2.2 smoke: 원인 진단이 틀렸다

「asyncio 루프 잔존」이 아니었다. 트레이스백을 끝까지 보니 `sync_playwright()` 가 **이미 실행 중인 이벤트 루프**를 만나 거부한 것이다.

```
self._loop = asyncio.get_running_loop()
...
if self._loop.is_running():
    raise Error("It looks like you are using Playwright Sync API inside the asyncio loop.")
```

그 루프의 주인은 **pytest-playwright 의 `playwright` fixture 이고, 이것이 session 스코프다**(`pytest_playwright.py` 에서 `@pytest.fixture(scope="session")` 확인). LinkedIn·Threads 스모크가 이 fixture 를 쓰면 세션 끝까지 루프가 살아 있고, 그 뒤 X 스모크가 `verify_x_auth.probe_producer()` 안에서 자기 `sync_playwright()` 를 열다 끊긴다.

**「순서 의존」은 증상이지 원인이 아니었다.** 원인은 중첩 호출이다.

### 2.3 그리고 e2e 가 통째로 죽어 있었다

같은 패턴을 찾다가 `pytest tests/e2e` 를 돌렸다.

```
1 failed, 38 passed, 3 skipped, 53 errors
```

**53건 전부 같은 오류**였다. e2e 8개 파일이 각자 아래 fixture 를 갖고 있었다.

```python
@pytest.fixture(scope="module")
def browser():
    """pytest-playwright 플러그인에 의존하지 않고 직접 브라우저를 띄운다."""
    with sync_playwright() as p:
        ...
```

알파벳순으로 `test_core_ui.py` 가 pytest-playwright 의 `page` fixture 를 쓰는 순간 session 루프가 잡히고, **그 뒤에 오는 모든 모듈이 전멸한다.** 38 passed 는 그 앞이고 53 errors 는 그 뒤다.

즉 e2e 커버리지의 **58%가 실행조차 되지 않고 있었다.** 통과 표시가 아니라 error 라서 「테스트가 돈다」는 착각을 만들지도 않았지만, 아무도 보지 않았다.

## 3. 해결

### 3.1 경로 상수 (커밋 대상 2줄)

| 파일 | 변경 |
|---|---|
| `tests/contract/test_api_surface.py:10` | `"docs"` → `"_docs"` |
| `pytest.ini:6` | `norecursedirs = tmp docs old` → `tmp _docs old` |

고치고 나니 `tests/contract` 5건 전부 통과했다. **라우트 문서는 이미 코드와 일치했다** — 테스트가 죽어 있는 동안 문서가 어긋난 것은 아니었다.

### 3.2 Playwright 중첩 제거 — 우회가 아니라 원인 제거

`probe_producer()` 가 인스턴스를 **주입받을 수 있게** 했다. 단독 실행(`main()`) 경로는 종전대로 자기 것을 연다.

```python
def probe_producer(playwright=None) -> tuple[bool, str]:
    if playwright is not None:
        return _probe_producer_with(playwright)
    with sync_playwright() as owned_playwright:
        return _probe_producer_with(owned_playwright)
```

e2e 8개 파일의 `browser` fixture 도 같은 방식으로 바꿨다. session 스코프 `playwright` 를 module 스코프 fixture 가 받는 것은 정상이다.

```python
@pytest.fixture(scope="module")
def browser(playwright):
    instance = playwright.chromium.launch(headless=True)
    yield instance
    instance.close()
```

`headless=True` 고정은 유지했다 — 창이 뜨면 사용자 포커스를 뺏는다.

**회귀 가드**: `tests/unit/test_verify_x_auth_injection.py` 3건 신설. 주입했는데도 `sync_playwright()` 를 열면 실패하도록 못 박았다. 브라우저를 띄우지 않아 unit 에 둔다.

### 3.3 e2e 를 되살리자 드러난 것 2건

53건이 실행되기 시작하면서 **한 번도 돌아본 적 없는 테스트**가 실패했다.

**② 데이터 의존 테스트 하나가 첫 후보에만 매달렸다**

후보를 순회하도록 고쳤다(`_search_until_card`). 테스트 의도(조회수 없는 플랫폼은 조회수 배지가 없다)는 그대로 두고 **특정 글 의존만** 없앴다.

## 6. 교훈

- **「순서 의존」은 증상 이름이다.** 트레이스백을 끝까지 읽기 전에는 원인 이름으로 쓰지 않는다. 여기서는 asyncio 가 아니라 중첩 호출이었다.
- **error 로 죽은 테스트는 fail 보다 위험하다.** 53건이 몇 달간 실행되지 않는 동안 실제 사용자 영향이 있는 캐시버스터 결함이 그대로 있었다.
- **폴더 개명은 문자열 상수를 남긴다.** 같은 파일의 docstring 은 고쳐졌는데 상수는 안 고쳐졌다 — 사람 눈이 훑는 곳과 코드가 읽는 곳이 다르다.
