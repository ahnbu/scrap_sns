## 1. 상황

### 1.1 무엇을 하려는가

기존 3개 플랫폼(X·Threads·LinkedIn)이 "내가 저장한 게시물"을 아카이브하듯, **내가 유튜브 재생목록에 담아둔 영상**을 같은 방식으로 수집해 동일 뷰어에서 검색 가능하게 만든다.

### 1.2 벤치마킹 수집기와 혼동하지 않는다

`cowork/01_사업/_SNS/` 쪽 문서들(`20260721_01`, `20260721_03`, `20260722_02`)이 다루는 유튜브는 **"벤치마킹 대상 채널 모니터링"** — 남이 올린 영상의 성과·형식을 학습하는 목적이다. 이 계획은 그것이 아니라 **본인 저장 영상 아카이브**를 다룬다. 두 작업은 대상·목적·저장 위치가 모두 다르므로 코드를 공유하지 않는다.

`scrap_sns/BACKLOG.md`에는 유튜브 관련 항목이 **존재하지 않는다**(전수 검색 0건, 2026-08-25 재확인). 이 계획이 해당 범위의 최초 정의다.

### 1.3 선행 작업은 이미 완료됐다

커밋 `cc3c60f`(2026-08-24 18:57) "feat(metrics): X·Threads·LinkedIn 참여지표 수집 및 뷰어 반영"으로 다음이 반영 완료됐다. **2026-08-25 전량 재확인함.**

| 항목 | 위치 (2026-08-25 실측) | 유튜브에 미치는 영향 |
|---|---|---|
| `like_count`·`comment_count`·`share_count`·`quote_count`·`bookmark_count`·`view_count` | `utils/post_schema.py:20-25` | 유튜브 `viewCount`/`likeCount`/`commentCount`를 **스키마 확장 없이** 그대로 채울 수 있다 |

drive7·ai.new2는 최근 대량 추가된 목록이라 대부분이 6개월 이내다. 필터를 걸어도 **477건**이 남으므로, 비용 절감 수단으로 기대할 수 없다. 반면 `기획new`는 177 → 34건으로 크게 줄어 필터가 유효하다.

### 3.4 API 쿼터는 사실상 제약이 아니다

`playlistItems.list` 1콜 = 1 unit. 대상 628건 전량 재조회에 **14 unit** 소모(일일 한도 10,000). `videos.list`로 지표·설명을 붙여도 50건당 1콜이므로 추가 13콜 수준이다. 매일 전량 재수집해도 쿼터 여유가 충분하다.

#### 3.6.1 초안의 근거는 틀렸다

초안은 *"뷰어가 통합 JSON을 통째로 로드하는 구조이므로"* 자막을 넣으면 뷰어가 느려진다고 적었다. **현재 구조가 아니다.**

| 경로 | 실제 동작 |
|---|---|
| `/api/posts` (`scrap_sns_server.py:1324`) | `META_FIELDS`만 반환. **`full_text`는 응답에 없고** `full_text_preview`(200자)·`full_text_length`만 나간다 |
| `/api/post/<sequence_id>` (`:1337`) | 본문은 카드 클릭 시 개별 조회 |
| `/api/search` (`:1358`) | 서버측 검색. `_searchable`은 `full_text`로 생성(`:781-786`) |

즉 자막을 `full_text`에 넣어도 **브라우저 로딩량은 거의 늘지 않는다.**

#### 3.6.2 진짜 비용은 스냅샷 중복 저장이다

`total_full_YYYYMMDD.json`은 **매일 새 파일로 생성되고 git에 커밋된다**(`.gitignore:112`가 커밋 대상으로 지정).

| 항목 | 실측 (2026-08-25) |
|---|---|
| 현재 git 추적 중인 `output_total/*.json` | **47개 파일 × 6.7~7.1MB** |
| `web_viewer/images` | 572MB, **커밋 안 함** |
| 자막 477건 예상 총량 | 건당 5~38KB, 평균 10KB 가정 시 **약 5MB** |

| 저장 방식 | git 비용 |
|---|---|
| **자막을 `transcripts/{videoId}.txt`로 분리** | videoId당 **1회 기록**. 이후 스냅샷에서 재저장되지 않음 → 총 약 5MB |
| 자막을 `full_text`에 포함 | 자막 5MB가 **스냅샷마다 통째로 재직렬화**. 현재 페이스(47개)면 수백 MB |

**결론(자막 전문을 `full_text`에 넣지 않는다)은 유지하되, 근거는 "뷰어 로딩 저하"가 아니라 "스냅샷 중복 저장"이다.**

| **Gemini 요약 형식·길이** | 한국어 **평문 3~5문장, 400자 이내**. 불릿·헤딩·마크다운 없음(`full_text`에 그대로 이어붙이므로). 모델은 `~/.env`의 `GEMINI_MODEL` 값을 쓰고, 없으면 `gemini-flash-latest` |
| **요약 캐시 위치·형식** | `output_youtube/summaries/{videoId}.json` — `{"video_id", "model", "generated_at", "summary", "transcript_sha1"}`. **파일 1개 = 영상 1개**(단일 대용량 JSON을 쓰면 병렬 기록 시 경합) |
| **캐시 활용 규칙** | 파일이 있고 `transcript_sha1`이 현재 자막과 같으면 재사용, 다르면 재생성. `--mode all` 이어도 캐시는 존중한다(강제 재생성은 `--refresh-summaries` 플래그) |
| **캐시 git 처리** | **커밋한다.** 4.6절 근거(재생성에 API 비용·시간이 들고 크기가 작다)가 그대로 적용된다. `.gitignore` 예외에 `summaries/` 3줄 추가 |
| **provider 서버 실행 방식** | **상시 실행하지 않는다.** 수집 시작 시 `GET http://127.0.0.1:4416/ping` 확인 → 실패 시 `node ~/bgutil-ytdlp-pot-provider/server/build/main.js` 를 detached로 기동 → 최대 30초 재확인 → 그래도 실패하면 자막 단계만 skip. **수집기가 띄운 경우에만 종료 시 내린다**(이미 떠 있던 서버는 건드리지 않는다) |
| **`yt-dlp` 의존성** | `requirements.txt`에 **등재한다**(`yt-dlp`, 버전 미고정 — YouTube 대응상 최신 추종이 필요). `bgutil-ytdlp-pot-provider`도 함께 등재 |
| **Gemini 429 대응** | 지수 백오프 재시도 3회(2초 → 4초 → 8초). 3회 실패 시 해당 건은 요약 없이 저장하고 `summary_status: "failed"` 를 남긴다 (plan-check 참고 제안 1 수용) |

## 5. 해결 — 단계별 계획

### ~~1단계: PO token 해결 가능성 검증~~ — **완료 (2026-08-24)**

사용자 승인 후 설치·검증했다. 성공 기준(10건 중 7건)에 대해 **12/12 전건 성공**. 상세는 3.5.2 참조.

남은 과제(4.5 결정으로 **필수**가 됨): 수집기가 provider 서버(포트 4416)를 **자동 기동·확인**해야 한다. 서버가 죽은 상태로 수집하면 자막이 조용히 0건이 되므로, 수집 시작 시 `GET /ping` 확인 → 실패 시 기동 → 그래도 실패하면 **자막 단계를 중단하고 오류를 명시 출력**한다. 단 **메타·설명 수집은 계속 진행**해 자막 실패가 전체 수집을 무산시키지 않게 한다.

### 2단계: 수집기 신설 — `youtube_scrap.py`

**`PLAYLISTS` 상수는 2.1절의 3개를 생략 없이 전부 하드코딩한다.** 아래는 실제 코드에 그대로 들어갈 값이다 — `...` 표기를 남기지 않는다.

```python
PLAYLISTS = [
    {"id": "PLed50f9DS0U_2zUeb8wnx9eZE8KujNUrw", "name": "drive7"},
    {"id": "PLed50f9DS0U84I1iUexAcbbftO8Wfu0Uk", "name": "ai.new2"},
    {"id": "PL-CeeIoxo5BbEiL6dQzgz4QBzgEcE7Jz8", "name": "기획new"},
]
DEFAULT_PLAYLISTS = ["drive7"]   # 4.7절 — 1차 실행은 파일럿 1개만
```

```
인자: --mode {update|all}          ← total_scrap.py가 그대로 전달한다
      --playlists <name[,name]|all> ← 기본값 drive7 (4.7절)
      --refresh-summaries           ← 캐시 무시하고 요약 재생성 (기본 off)

0. provider /ping 확인 → 실패 시 detached 기동 → 30초 내 미응답이면 자막 단계 skip 플래그
1. playlistItems.list 페이지네이션 → 대상 재생목록 항목 + snippet.publishedAt(추가일)
2. 추가일 6개월 필터 + Deleted/Private video 제외
3. [update 모드] 기존 output_youtube full + transcripts/ 대조 → 신규 videoId만 4~6단계 대상
4. videos.list (50건 배치) → statistics(view/like/comment) + description 전문 + thumbnails
5. 자막 취득 → output_youtube/transcripts/{videoId}.txt
6. Gemini 요약 (자막 있는 건만) → output_youtube/summaries/{videoId}.json 캐시 (4.8절)
7. output_youtube/python/youtube_py_full_YYYYMMDD.json 저장
8. 0단계에서 수집기가 provider를 띄운 경우에만 종료
```
