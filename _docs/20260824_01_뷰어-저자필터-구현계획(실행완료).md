## 1. 상황 (Situation)

### 1-1. 요구사항

웹 뷰어 카드 헤더의 저자 이름을 클릭하면, 해당 플랫폼에서 그 저자가 쓴 게시글만 남도록 필터링한다.

현재 카드 헤더는 아래처럼 렌더링되며, 이름은 단순 텍스트라 클릭해도 아무 일도 일어나지 않는다.

```html
<h3 class="text-sm font-semibold text-white truncate max-w-[150px]">한성국</h3>
```

## 2. 문제 (Complication)

### 2-1. 화면에 보이는 이름을 필터 키로 쓸 수 없다

카드에 표시되는 값은 `display_name`이지만, 이걸 매칭 키로 쓰면 **같은 저자가 둘로 쪼개진다**. 위 105종이 정확히 그 케이스다. 예컨대 `jinaleesoc`의 게시글은 `display_name`이 `Jina Lee`인 것과 `jinaleesoc`인 것으로 나뉘어 있어, 어느 쪽 카드를 클릭하든 나머지 절반이 사라진다.

반대로 `username`을 그대로 배지에 표시하면 LinkedIn에서 `ACoAAA_8D_MB...`가 노출된다. **표시값과 매칭 키를 분리해야 한다.**

### 2-2. 필터가 걸린 상태를 사용자가 인지·해제할 수단이 없다

저자 필터가 적용되면 화면에 카드가 몇 장만 남는다. 해제 UI가 없으면 사용자는 플랫폼 칩을 바꾸거나 검색어를 지워도 결과가 돌아오지 않는 상태에 갇힌다. 필터 상태를 눈에 보이게 만들고, 원클릭 해제를 제공해야 한다.

### 2-3. 카드 헤더가 `innerHTML` 문자열로 생성된다

`createCard()`는 헤더 전체를 템플릿 문자열로 조립한다(`script.js:2478`). 이름에 인라인 `onclick`을 넣을 수 없고, 기존 `select-btn` / `favorite-btn`처럼 조립 후 `header.querySelector()`로 리스너를 붙여야 한다. 또한 카드 본문에 상세 열기 핸들러가 있어 `e.stopPropagation()`이 없으면 클릭이 겹친다.

### 2-4. 태그 칩 컨테이너의 조기 반환

배지를 놓을 `globalTagsContainer`를 그리는 `updateGlobalTags()`는 태그가 하나도 없으면 `container.innerHTML = ''` 후 즉시 반환한다(`script.js:2938`). 이 경로를 그대로 두면 **태그가 없는 사용자에게는 저자 배지가 아예 안 나온다.**

### 2-5. 검색 중일 때의 결과 상한

검색어가 있으면 `runServerSearch()`가 `/api/search`를 `limit=500`으로 호출하고, 그 결과에 클라이언트 필터가 적용된다(`script.js:1985`). 따라서 검색 + 저자 필터를 동시에 쓸 때, 해당 저자 글이 상위 500건 밖에 있으면 보이지 않는다.

### 2-6. 저자명 표시가 플랫폼 간·플랫폼 내에서 갈려 있다

뷰어는 세 플랫폼을 한 화면에 섞어 보여주는데, 카드에 뜨는 이름의 성격이 통일돼 있지 않다.

| 플랫폼 | 게시글 | 사람 이름으로 표시 | 계정 아이디로 표시 |
| --- | ---: | ---: | ---: |
| Threads | 1,247 | 542 | **705** |
| LinkedIn | 660 | 660 | 0 |
| X | 95 | 94 | 1 |
| **합계** | **2,002** | 1,296 (65%) | 706 (35%) |

LinkedIn과 X는 사실상 전부 이름인데 **Threads만 반반으로 갈려 있다.** 같은 저자의 글인데도 어떤 카드는 `Jina Lee`, 어떤 카드는 `jinaleesoc`으로 보인다.

원인은 1-3에서 확인한 대로 `display_name` 결측이며, 그 뿌리는 수집기 하드코딩이다(3-6 참조).

### 2-7. 이름이 길면 우측 버튼이 카드 밖으로 밀려난다

실제 뷰어(4열 · 카드 폭 368px)에서 DOM 좌표를 실측한 결과다.

| 사례 | 버튼이 카드 밖으로 넘친 폭 |
| --- | ---: |
| `Khairallah AL-Awady` (X) | 9px |
| `빌더+디자이너 에릭 \| 아마존 베스트셀러 작가…` (Threads) | 23px |

맨 오른쪽 선택 버튼(`select-btn`)이 잘려 클릭할 수 없게 된다. **저자 필터와 무관하게 지금도 발생 중인 결함**이며, 버튼 컨테이너에 `flex-shrink-0`이 없어 왼쪽 텍스트가 커질 때 버튼 영역이 밀리는 것이 원인이다.

## 3. 해결 (Resolution)

### 3-1. 설계 결정

| 결정 | 내용 |
| --- | --- |
| 매칭 키 | `(정규화된 sns_platform, username)` 쌍 |
| 표시값 | 클릭한 카드의 `display_name` (없으면 `username`) |
| 상태 | `currentAuthor = { platform, username, label } \| null` |
| 토글 | 같은 저자 이름 재클릭 시 해제 (태그 칩과 동일 UX) |
| 서버 변경 | 없음 |

플랫폼을 키에 포함하므로 "해당 플랫폼에서 해당 저자만"이라는 요구가 그대로 충족된다. Threads와 X에 같은 핸들을 쓰는 계정이 있어도 섞이지 않는다.

### 3-2. 변경 지점

#### (1) 상태 변수 추가 — `script.js:180` 부근

```js
let currentAuthor = null;   // { platform, username, label } | null
```

#### (2) 필터 조건 추가 — `script.js:2015` `getFilteredPosts()`

```js
const matchesAuthor = !currentAuthor
    || (normalizePostKeyPlatform(post.sns_platform) === currentAuthor.platform
        && String(post.username || post.user || '') === currentAuthor.username);

return matchesFilter && matchesTag && matchesVisibility && matchesAuthor;
```

`normalizePostKeyPlatform()`은 이미 존재하므로 새로 만들지 않는다. `searchResults`에도 동일 함수가 적용되므로 검색 결과에 대한 저자 필터가 자동으로 동작한다.

#### (3) 이름 클릭 가능화 — `script.js:2483` `createCard()`

헤더 템플릿의 `<h3>`에 클래스와 접근성 속성을 추가한다.

```html
<h3 class="author-link text-sm font-semibold text-white truncate max-w-[150px] cursor-pointer hover:text-primary hover:underline"
    role="button" tabindex="0" title="이 저자의 글만 보기">…</h3>
```

헤더 조립 직후, 기존 `select-btn` 바인딩과 같은 자리에 리스너를 붙인다.

```js
const authorLink = header.querySelector('.author-link');
const authorKey = {
    platform: normalizePostKeyPlatform(post.sns_platform),
    username: String(post.username || post.user || ''),
    label: post.display_name || post.username || post.user || 'Unknown',
};
// username이 없으면 필터 키를 만들 수 없다 — 클릭 비활성화
if (!authorKey.username) {
    authorLink.classList.remove('cursor-pointer', 'hover:text-primary', 'hover:underline');
    authorLink.removeAttribute('role');
    authorLink.removeAttribute('tabindex');
    authorLink.removeAttribute('title');
    return;   // 리스너를 달지 않는다
}
const toggleAuthor = (e) => {
    e.stopPropagation();
    const isSame = currentAuthor
        && currentAuthor.platform === authorKey.platform
        && currentAuthor.username === authorKey.username;
    currentAuthor = isSame ? null : authorKey;
    clearSelection();
    renderPosts();
};
authorLink.addEventListener('click', toggleAuthor);
authorLink.addEventListener('keydown', (e) => {
    if (e.key === 'Enter' || e.key === ' ') {
        e.preventDefault();   // Space가 페이지를 스크롤하지 않도록
        toggleAuthor(e);
    }
});
```

위 가드로 `username`이 빈 게시글은 클릭 대상에서 제외한다(실측 결측 0건이나 향후 유입 대비). `return`이 카드 생성 흐름을 끊지 않도록, 이 블록은 헤더 바인딩을 담당하는 별도 함수 안에 둔다.

#### (4) 활성 저자 배지 — `updateGlobalTags()` (`script.js:2929`)

- 함수 선두에서 저자 배지를 먼저 렌더한다.
- **2-4에서 지적한 조기 반환을 수정한다.** 태그가 0개여도 저자 배지는 남아야 하므로, `sortedTags.length === 0`일 때 무조건 `innerHTML = ''` 후 반환하지 말고 배지 렌더 이후에 태그 루프만 건너뛰도록 바꾼다.
- 배지 형태: `👤 한성국 ×`. 클릭 시 `currentAuthor = null; renderPosts();`
- 배지에 표시하는 값은 `currentAuthor.label`이며, 뷰어에 이미 있는 `escapeHtml()`을 씌운다. LinkedIn 내부 ID는 노출되지 않는다.

### 3-3. 검토 후 기각한 옵션

| 옵션 | 기각 근거 |
| --- | --- |
| 서버 `/api/search`·`/api/posts`에 `author` 파라미터 추가 | 전체 게시글이 이미 클라이언트 메모리에 있다. 서버 왕복과 검색어 조합 처리만 늘고 얻는 게 없다 |
| `display_name` 기준 매칭 | 한 저자 안에서 `display_name`이 흔들리는 케이스가 105종 있어 저자가 둘로 쪼개진다(1-3). 원인이 셋(fallback 102 / 실제 이름 변경 2 / X 오염 1)이고 그중 둘은 고칠 수 있는 결함이지만, **셋 중 무엇이 남든 필터가 깨진다**는 점은 같다. 특히 LinkedIn의 한/영 이름 전환 2종은 수정 대상이 아닌 정상 데이터이므로, `display_name`은 원리적으로 안정 키가 될 수 없다 |
| 이름 클릭 시 검색창에 저자명 자동 입력 | ① 본문에 그 이름이 언급된 남의 글까지 잡힌다 ② 서버 검색 `limit=500` 상한에 걸린다 ③ 사용자가 입력 중이던 검색어를 덮어쓴다 |
| 저자 클릭 시 플랫폼 칩까지 자동 전환 | 매칭 키에 플랫폼이 이미 포함돼 중복이다. 칩 상태를 건드리면 필터 해제 시 원래 칩으로 되돌리는 복원 로직이 추가로 필요해진다 |
| `post_key` 접두사(`threads:`, `x:`)로 저자 판별 | `post_key`는 게시글 단위 식별자라 저자 단위 그룹핑에 쓸 수 없다 |
| 배지에 실제 이름 자동 보정 (`resolveAuthorLabel()`) | **초안에 넣었다가 철회.** 같은 저자에 실제 이름 후보가 2개 이상인 경우 임의의 하나가 뽑혀 **클릭한 이름과 다른 이름이 배지에 뜬다**. LinkedIn 2종(`배수정` 클릭 → `Soojeong Bae` 표시), X `kana_option` 1종(13개 중 임의), Threads 3종이 해당한다. 보정이 실제로 필요한 건 Threads뿐인데 부작용은 전 플랫폼에 생긴다. 플랫폼 조건을 붙여도 카드 헤더(`jinaleesoc`)와 배지(`Jina Lee`)가 어긋나는 문제가 남는다. **클릭한 값과 보이는 값의 일치**가 읽기 좋은 이름보다 우선이다 |
| 필터 상태를 URL 쿼리에 반영(딥링크) | 현재 뷰어는 어떤 필터도 URL에 반영하지 않는다. 이 기능만 예외를 만들면 일관성이 깨진다. 필요해지면 태그·플랫폼과 함께 별건으로 처리한다 |

### 3-4. 남는 제약 (수용)

검색어와 저자 필터를 동시에 쓰면 서버 검색 상위 500건 범위 안에서만 저자 필터가 동작한다(2-5). 검색어를 지우면 전체 2,002건 기준으로 정상 동작한다. 이 제약을 없애려면 서버 작업이 필요하므로 본 계획 범위에서 제외하고, 실사용에서 문제가 확인되면 별건으로 다룬다.

### 3-5. 범위 밖: X 수집 데이터 오염

세션 `4efc85ee-1841-4417-bd43-ced95062bdc2`에서 별도 처리한다. 본 작업은 `twitter_scrap.py`, `twitter_scrap_single.py`, `utils/twitter_parser.py`, `utils/twitter_cli_adapter.py`, `output_twitter/`, `output_threads/`, `output_total/` 을 일절 건드리지 않는다.

해당 세션의 코드 검증 결과(2026-08-24 회신)에 따라 아래로 정리한다. 최초 제보 시 필자가 세운 "`twitter_scrap.py`의 DOM selector 문제" 가설은 **틀렸다**. 실제 원인은 커밋 `ee9fb37`(2026-04-18)에서 교체·삭제된 레거시 상세 수집기 `twitter_scrap_single.py`가 목록 수집 결과를 덮어쓴 것이며, 오염 36건은 예외 없이 `source == "full_tweet_scan"` 이다.

### 3-6. 저자명 표시 정책 — 세 플랫폼 모두 사람 이름

**결정: 카드에 표시하는 저자명은 세 플랫폼 모두 사람 이름으로 통일한다.**

#### 뷰어 코드는 바꾸지 않는다

`createCard()`가 이미 `post.display_name || post.username || post.user` 순으로 표시한다(`script.js:2483`). 즉 **정책은 이미 코드에 반영돼 있고, 미달인 것은 데이터뿐이다.** 표시 로직에 손댈 것이 없다.

| 플랫폼 | 정책 달성 여부 | 필요한 조치 |
| --- | --- | --- |
| LinkedIn | 660/660 달성 | 없음 |
| X | 94/95 달성 | 없음. 미달 1건은 X 수집 오염이며 병행 세션이 처리(3-5) |
| Threads | 542/1,247 달성 | **705건 데이터 복구**(3-7) |

#### 검토 후 기각한 두 방식

| 방식 | 기각 근거 |
| --- | --- |
| Threads·X를 계정 아이디로 통일 | 일관성은 100% 즉시 달성되지만 **542건(Threads)+94건(X)의 이름이 화면에서 사라진다.** 그중 한글 이름이 397건이다(`중얼거리는 남자`→`CurbsideCroaker`, `프로그래밍좀비`→`gimhyeo02389130`). 되돌리려면 다시 작업해야 하고, 결측 자체는 그대로 남아 재발 방지도 안 된다 |
| 이름 + 아이디 병기 | 아이디는 사용자가 소비하지 않는 값이다. 원본 이동은 `View Original` 버튼이 담당하고, 저자 필터는 이름을 클릭하면 동작한다. 얻는 것 없이 2-7의 버튼 밀림을 최대 47px까지 악화시킨다(실측) |

**핵심은 비대칭성이다.** 아이디로 가면 이름을 잃고 되돌리기 어렵지만, 이름으로 가면 데이터가 채워질 뿐 잃는 것이 없다.

#### 이 정책이 저자 필터에 미치는 영향

없다. 필터 키는 `username`이고 표시명과 독립적이다(3-1). 표시 정책이 어떻게 결정되든 필터 동작은 같다.

#### 채택: 저자 단위 프로필 백필

`display_name`은 게시글 속성이 아니라 **저자 속성**이므로, 게시글 705건이 아니라 **저자 407명** 단위로 조회하면 된다.

| 항목 | 내용 |
| --- | --- |
| 신규 스크립트 | `scripts/backfill_threads_display_name.py` |
| 입력 | 최신 `output_threads/python/threads_py_full_*.json`에서 `display_name == username`인 게시글의 고유 `username` 목록 |
| 수집 방법 | Threads 프로필 페이지 접속 → 페이지 페이로드의 `full_name` 추출 (게시글 상세 수집이 아니므로 `fail_count`와 무관) |
| 백필 대상 | upstream `output_threads/python/threads_py_full_*.json` → `total_scrap.py --mode merge-only` 또는 `scripts/merge_total_only.py`로 `output_total` 재생성 |
| 실행 모드 | headless. 창을 띄우지 않는다 |
| **요청 간격** | 저자 1명당 `time.sleep(2)` 이상. 407명 단기 집중 조회는 Threads(Instagram) WAF의 IP 차단을 유발할 수 있다. `--delay` 옵션으로 조정 가능하게 하고 기본값 2초 |
| 중단·재개 | 진행 상황을 중간 저장해 중단 시 이어서 실행할 수 있게 한다 |
| 백업 선행 | `output_threads/python/threads_py_full_20260824.json` 사본 보관 후 수정 |
| 부분 실패 처리 | 조회 실패 저자는 건너뛰고 로그에 남긴다. 기존 값을 지우지 않는다(덮어쓰기는 `full_name`이 비어 있지 않을 때만) |
| 되돌리기 | 백업 파일 복원 + `output_total` 재생성 |
| 실행 로그 | `logs/backfill_threads_display_name_YYYYMMDD.log`에 저자별 성공·실패·건너뜀을 기록한다. **실패 항목은 `username`을 그대로 남겨** 재처리·수동 확인이 가능하게 한다. **커밋하지 않는다** — `logs/`는 이미 레포에서 산출물 디렉터리로 쓰인다. 백필 결과 요약(대상 저자 수, 성공 수, 실패 목록)은 계획 문서 실행 기록에 남긴다 |
| 종료코드 | 정상 종료 0, 조회 실패가 대상의 50%를 넘으면 1 (부분 실패는 0이되 로그에 남김) |

#### 신규 발생 차단 — `thread_scrap.py` 수정은 취소한다

초안에서는 `thread_scrap.py:307`·`:711`의 하드코딩을 제거해 DOM 경로에서도 `full_name`을 쓰게 하려 했다. **검수 지적을 받아 재확인한 결과 이 방식은 성립하지 않는다.**

| 확인 | 근거 |
| --- | --- |
| DOM 경로는 JSON 페이로드에 접근하지 않는다 | `thread_scrap.py:664` `raw_text = element.inner_text()`, `thread_scrap.py:291` `candidate.get("text")` |
| 카드 렌더 텍스트에 `full_name`이 없다 | 스냅샷 실측: `팔로우 \| yangyang123001 \| 6일 \| 더 보기 \| <본문>`, `팔로우 \| on._.serin \| 4일 \| 수정됨 \| …`. 첫 줄은 계정 아이디다. `ssssssssoka` 카드에서도 `full_name`인 `soka`는 카드 텍스트에 없었다 |

즉 `lines[0]`을 쓰든 페이로드를 뒤지든 **DOM 경로에서는 `full_name`을 얻을 수 없다.** 수집기를 고칠 대상이 없으므로 `thread_scrap.py`는 변경하지 않는다.

**대신 백필 스크립트가 신규 발생분도 함께 처리한다.** 스크립트는 실행 시점에 `display_name == username`인 게시글을 전부 대상으로 잡으므로, 정기 수집 이후 한 번 더 돌리면 신규분이 흡수된다. 이 운용 방식을 `README.md`의 수집 절차에 한 줄로 명시한다.

### 3-8. 버튼 밀림 수정

2-7의 결함을 함께 고친다. 카드 헤더 우측 버튼 컨테이너(`script.js:2489`의 `<div class="flex items-center gap-1">`)에 `shrink-0`을 추가한다. 한 줄이며 저자 필터와 독립적이다.

### 3-9. 그 밖의 범위 밖

- **Threads 705건 중 재수집으로도 복구 안 되는 약 10%.** 해당 계정이 실제로 표시 이름을 비워둔 경우다. 데이터에 값이 없어 어떤 방법으로도 채울 수 없고, 이 카드들은 계정 아이디로 표시된다.
- `utils/twitter_cli_adapter.py:52`의 ID 미대조 잔존 결함. 병행 세션이 재수집 전 가드를 넣기로 했다.
- 저자별 게시글 수 표시, 저자 목록 패널, 저자 즐겨찾기 등 요구되지 않은 확장.
