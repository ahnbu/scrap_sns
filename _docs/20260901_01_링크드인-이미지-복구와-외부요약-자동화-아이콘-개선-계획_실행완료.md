## 2. 문제 (Complication)

### 문제 A — 외부 요약이 파이프라인에 연결돼 있지 않다

`npm run scrap:all`(= `total_scrap.py`)은 수집 후 `cleanup_old_output_json.mjs` 만 자동 실행한다. 레포 전체에서 `build_external_summaries` 를 호출하는 곳은 문서(`AGENTS.md` 32~33행)뿐이고 실행 경로가 없다.

결과: 갱신은 사람이 아래 3개를 손으로 칠 때만 일어난다.

```
node scripts/lilys_library.mjs list
node scripts/livewiki_library.mjs list
node scripts/build_external_summaries.mjs
```

마지막 수동 실행이 8/28 18:21이므로, 그 이후 요약한 영상은 요약이 실제로 존재해도 뷰어가 알 방법이 없다.

### 문제 B — 링크드인 이미지가 "한 번 놓치면 영구 복구 불가"

4단 연쇄다.

| 단계 | 위치 | 내용 |
|---|---|---|
| B-1 | LinkedIn CDN 정책 | 서명 URL이 만료되면 어떤 헤더로도 403 |
| B-2 | `linkedin_scrap.py:333-335` | 기존 글에 `media` 값이 하나라도 있으면 `return`. 만료된 죽은 URL도 "있으니 됐다"로 판정돼 영원히 교체되지 않음 |
| B-3 | `total_scrap.py:920` `select_image_download_posts()` | update 모드에서 기존 `post_key` 를 통째로 제외. 첫 수집 때 놓친 글은 다음 실행에서 시도조차 안 함 |
| B-4 | `web_viewer/script.js:1948` `getBestImageSource()` | 로컬 파일이 없으면 `licdn.com` 원본 URL을 그대로 `img.src` 에 넣음(Threads 는 wsrv.nl 프록시를 타지만 licdn 은 명시 제외). 브라우저가 403 → "Image Unavailable" 자리표시자 |

B-2 와 B-3 이 맞물려 "URL도 안 바뀌고 다운로드도 재시도 안 하는" 고착 상태를 만든다. 그 사이 URL이 만료되면 회복 불가가 된다. Threads(확보율 4%)도 B-3·B-4 를 공유한다.

### 문제 C — 요약 아이콘이 서비스를 식별하지 못한다

`web_viewer/script.js:2584-2587`:

```js
{ key: 'lilys',    label: 'Lilys 요약',    glyph: 'auto_awesome' },  // ✨
{ key: 'livewiki', label: 'LiveWiki 요약', glyph: 'article' },        // 📄
```

`auto_awesome`(반짝이)과 `article`(문서)은 둘 다 일반 기호라 어느 서비스인지 읽히지 않는다. 이름은 `title`/`aria-label` 에만 있어 마우스를 올려야 알 수 있다.

### 웨이브 1 — 링크드인·Threads 이미지 고착 해제 + 만료 453건 재수집

**1-1. 만료 판정 유틸 추가**

- 위치: `total_scrap.py` (상단 유틸 구역, `get_image_identity_key()` 인근)
- 함수: `is_media_url_expired(img_url, now_ts=None) -> bool`
- 규칙: 쿼리에서 `e=` 를 읽어 epoch 정수면 `int(e) <= now` 일 때 만료. `e` 가 없거나 정수가 아니면 **만료로 보지 않는다**(licdn 외 도메인 오탐 방지).
- 근거: fbcdn 등 다른 CDN은 만료 파라미터 이름이 달라 일반화하면 오탐이 난다. 이번 범위는 `e=` 규약을 쓰는 licdn 만 확실히 처리한다.

**1-2. 다운로드 대상 선정 확대** — `total_scrap.py:920`

`select_image_download_posts()` 를 다음 합집합으로 변경한다.

- (기존) 신규 `post_key` 글 전부
- (추가) 기존 글 중 **`media` 는 있고 `local_images` 가 비었으며, 만료되지 않은 이미지 URL이 하나 이상인** 글

`local_images` 가 이미 있는 글, 만료 URL만 가진 글은 계속 제외한다. 매 실행마다 죽은 URL에 403 요청을 반복하지 않기 위해서다.

**1-3. 수집기 skip 조건 교정** — `linkedin_scrap.py:333-335`

```python
# 변경 전
if existing_post.get("media"):
    return
# 변경 후 (의도)
media = existing_post.get("media") or []
if media and not any(is_media_url_expired(u) for u in media):
    return
```

만료 URL을 가진 기존 글은 통과시켜 새 서명 URL을 다시 파싱하게 한다.

만료 판정 함수는 1-1 과 중복 구현하지 않는다. 정본은 **신규 모듈 `utils/media_expiry.py`** 에 두고 `total_scrap.py` 와 `linkedin_scrap.py` 양쪽에서 import 한다. `utils/post_schema.py` 에 넣지 않는 이유는 그 파일이 스키마 정본이고 네트워크·시간 의존 로직이 섞이면 계약 테스트 범위가 흐려지기 때문이다.

**주의**: `CRAWL_MODE == "update only"` 일 때 `linkedin_scrap.py:326-331` 의 `CONSECUTIVE_EXISTING_LIMIT`(=20) 조기 종료가 이 통과보다 먼저 걸린다. 기수집 글 20건이 연속되면 그 지점에서 수집이 끝나므로 저장글 목록 깊은 곳의 만료 글에 닿지 못한다. 만료 URL을 가진 글은 `self.consecutive_existing_count = 0` 으로 리셋해 스크롤이 계속되도록 함께 조정한다.

**1-4. 만료 453건 재수집 (1회성 전량 스캔)**

수집 대상은 피드가 아니라 **저장글 목록**이다(`linkedin_scrap.py:17` `TARGET_URL = "https://www.linkedin.com/my-items/saved-posts/"`). 사용자가 저장을 해제하지 않는 한 만료 453건 전부 목록에 그대로 남아 있으므로, 별도 백필 스크립트 없이 전량 스캔 1회로 새 서명 URL을 다시 얻을 수 있다.

`--mode all` 은 `linkedin_scrap.py:581` 에서 `CRAWL_MODE = "all"` 로 매핑되어 조기 종료 분기(`linkedin_scrap.py:326`)를 타지 않는다. 단, 1-3 수정이 **반드시 선행**돼야 한다. 수정 전에는 `linkedin_scrap.py:333-335` 가 `media` 보유 글을 전부 되돌려 보내므로 `--mode all` 을 돌려도 URL이 갱신되지 않는다.

```bash
python linkedin_scrap.py --mode all
python scripts/rebuild_total.py
```

`rebuild_total.py` 는 병합만 하는 스크립트가 아니다. `scripts/rebuild_total.py:41` 에서 `download_images` 를 import 해 `:140` 에서 호출하므로, 이 한 줄로 병합 → 이미지 실제 다운로드 → 통합본 저장까지 끝난다. 완료검수는 이 실행의 로그와 결과 통합본을 함께 본다.

`total_scrap.py --mode all` 을 쓰지 않는 이유: 그것은 4개 플랫폼 전부를 전량 재수집해 소요 시간과 계정 부하가 불필요하게 커진다. 링크드인만 전량으로 돌리고 통합본은 재병합만 한다.

**트레이드오프**: 전량 스캔은 저장글 목록 끝까지 스크롤하므로 update 모드보다 수집 시간과 네트워크 트래픽이 크게 늘어난다(현재 저장글 676건 기준). 대신 만료 453건이 한 번에 해소되고, 이후에는 1-3 수정 덕분에 정기 update 수집만으로 유지된다. 1회성 비용으로 본다.

**1-5. 뷰어 폴백 정리** — `web_viewer/script.js:1937-1954`

`getBestImageSource()` 가 로컬 파일이 없을 때 `licdn.com` 원본 URL을 그대로 반환하는 분기를 조정한다. 만료 URL이면 빈 문자열을 반환해 이미지 영역 자체를 렌더하지 않고, 카드에 "원본에서 보기" 링크만 남긴다. 만료 판정은 JS 쪽에 동일 규칙(`e=` 파싱)을 작은 헬퍼로 두되, 파이썬 정본과 규칙이 어긋나지 않도록 주석으로 `utils/media_expiry.py` 를 참조 정본으로 명시한다.

### 5.0 검증 실행 규약 (모든 웨이브 공통)

**뷰어 검증은 전부 headless 로 한다.** 사람 눈으로 보는 확인 항목을 두지 않는다. 이유는 둘이다 — 창이 뜨면 사용자 포커스를 빼앗아 병행 작업이 끊기고, 육안 확인은 종료코드로 남지 않아 완료검수가 증거 기반으로 판정할 수 없다.

- 기존 자산인 `scripts/verify_viewer_total_count_headless.mjs`, `scripts/verify_external_summary_icons.mjs` 와 같은 형태를 따른다: `BASE_URL = process.env.SNS_HUB_BASE_URL || 'http://127.0.0.1:5000/'`, `--shot <png path>` 옵션, `process.exit(await main())` 로 종료코드 반환, **실패했을 때만** 스크린샷 저장.

**산출물 처리 방침**: 실패 시 남는 스크린샷은 `_docs/evidence/` 아래에 저장하고 **커밋하지 않는다**. 디버깅용 일회성 파일이라 저장소에 남길 가치가 없다. 웨이브 0에서 `.gitignore` 에 `_docs/evidence/*.png` 한 줄을 추가한다. 통과한 실행은 스크린샷을 남기지 않으므로 별도 처리가 필요 없다.

| `linkedin_scrap.py` 조기 종료 로직이 만료 글 갱신을 가로막음 | 중간 | 만료 글에서 `consecutive_existing_count` 리셋 + 1-4 는 `--mode all` 로 조기 종료 분기 자체를 우회 |
| 만료 판정을 licdn 외 도메인에 잘못 적용 | 중간 | `e=` 가 정수인 경우만 만료 판정. 그 외는 만료로 보지 않음 |
| 전량 스캔의 수집 시간·트래픽 증가 | 중간 | 1회성 비용. 이후 정기 update 수집만으로 유지된다. 링크드인만 전량으로 돌리고 타 플랫폼은 건드리지 않음 |
| 계정 부하로 링크드인이 일시 차단 | 중간 | 기존 수집기의 스크롤 간격·대기 로직을 그대로 사용하고 별도 가속을 넣지 않음. 실패 시 다음 날 재시도 |
| Lilys 인증 만료로 웨이브 2 첫 실행 실패 | 낮음 | 실패해도 수집은 성공 처리. 재로그인 안내 출력 |

## 7. 범위 밖

- Threads 이미지 확보율(4%) 전용 개선 — 웨이브 1-1·1-2·1-5 가 그대로 적용되므로 효과를 먼저 측정한 뒤 판단한다. Threads 는 저장글 목록 구조가 달라 전량 스캔 비용이 링크드인과 다르므로, 같은 처방을 그대로 옮기지 않는다
- 아이콘 E(브랜드 파비콘) 도입 및 상표 사용 검토
- X(Twitter) 이미지 확보(68건 미확보) — 이번 진단 범위에 포함하지 않았다
