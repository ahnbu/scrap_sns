## 2. 문제

### 2.1 대기분이 저절로 줄어든다는 전제가 거짓이었다 (BL-0826-04)

`update` 모드의 처리 대상은 "직전 산출물에 **없는** 영상"으로만 계산된다.
`deferred` 로 저장된 순간 그 영상은 산출물에 **있으므로**, 다음 실행에서 대상에서 빠진다.
한 번 상한에 걸리면 영구 고립된다.

```
youtube_scrap.py:791  pending = {vid: e for vid, e in entries.items() if vid not in existing}
                :799  ordered_ids = apply_wave_filters(list(pending.keys()), ...)
                :835  usable_ids = [vid for vid in ordered_ids if details.get(vid)]
```

실측: `--mode update --playlists all` 실행 시 `신규 0건 (기존 458건 재사용)` 만 출력되고 요약 시도 자체가 없었다.

**영향은 과거형이 아니다.** 런처가 `--playlists all --max-summaries 15` 로 고정돼 있어
(`total_scrap.py:374`), 앞으로 재생목록에 15건을 넘게 저장할 때마다 초과분이 계속 고립된다.

### 2.2 provider 사고 시 캐시 자막을 버려 기존 요약이 사라진다 (이번 조사에서 신규 발견)

`youtube_scrap.py` 의 자막 단계가 `if ordered_ids and provider_ok:` 로 묶여 있었다.
PO token provider 가 뜨지 않으면 **디스크에 있는 자막 423건을 읽지도 않는다.**
그러면 전 건이 `transcript_status: blocked` → `summary_status: no_transcript` 로 저장되고,
`merged` 가 기존 레코드를 덮어 **완료된 요약 128건이 통합본과 뷰어에서 사라진다.**

요약 캐시 파일(`output_youtube/summaries/*.json`)은 남아 있어 재실행하면 복구되고 추가 과금도 없다.
그러나 `BL-0826-03` 은 배치를 6회 반복하는 작업이라 노출이 6회다.

### 2.3 쿼터가 빠듯하다

잔량 60%, 필요량 추정 48~70%p. 최악의 경우 마지막 1~2배치에서 마른다.
마르면 실패한 호출도 쿼터를 먹는다.

## 3. 해결

### 3.1 BL-0826-04 — 요약 대기분을 다시 대상에 넣는다 (완료)

| 변경 | 내용 |
|---|---|
| `needs_summary_retry()` 신규 | `summary_status` 가 `deferred`·`failed` 이고 자막 파일이 실재하면 재시도 대상 |
| `select_update_targets()` 신규 | `update` 모드 대상을 (신규, 재시도) 로 분리. `--skip-summaries` 실행은 재시도 없음 |
| `order_new_first()` 신규 | 신규를 앞, 재시도를 뒤로 정렬 |
| `run()` 수정 | 위 세 함수 반영 + 완료 로그에 `요약 대기 N건` 출력 |

**판단 1 — 순서는 신규 우선.**
`--max-summaries` 는 목록 **뒤**를 잘라 상한을 건다. 재시도분이 앞에 서면 방금 저장한 영상이
대기 295건 뒤로 밀려 몇 번을 돌려도 요약되지 않는다. 뒤에 두면 신규가 적은 평시 실행에서
남는 여유만큼 대기분이 줄어든다.

**판단 2 — 대상 상태는 `deferred` + `failed`.**
`failed`(agy 타임아웃)는 토큰을 거의 쓰지 않으므로 재시도가 맞다(실측 1건, 이후 성공해 현재 0건).
`no_transcript` 35건은 제외했다 — 자막이 없으면 요약할 재료가 없어 다시 불러도 결과가 같다.

**판단 3 — `--skip-summaries` 실행은 대기분을 건드리지 않는다.**
요약을 건너뛰는 실행이 대기분을 다시 쓰면 `deferred` 표시가 `skipped` 로 덮여 대기 상태가 소멸한다.

### 3.2 provider 사고 가드 (완료)

`download_transcript()` 에 `allow_download` 인자를 추가했다. provider 가 없으면 **새로 받는 것만**
막고 캐시는 그대로 읽는다. `--refresh-transcripts` 라도 provider 가 없으면 캐시로 되돌아간다 —
재수집이 불가능한 상황에서 캐시를 버리면 멀쩡한 자막을 잃기 때문이다.


배치 사이에 **PowerShell 로** `agy --print="/usage"` 로 잔량을 확인한다
(Git Bash 는 `/usage` 를 경로로 변환해 실패한다).

**완료 판정**
