## 2. 상황 (Situation)

### 2.1 사용자가 원한 것

뷰어의 정체성을 「내 SNS 저장글 모음」 → 「+ 벤치마킹」 → **「+ 저장 범위가 웹·파일까지」** 로 넓힌다. 볼트(`90_자료수집`)의 자료를 뷰어에 카드로 보이게 하고, SNS로 배포된 자료는 원문 카드에서 요약본으로 이어지게 하며, 카드의 이름 옆에서 그 사람의 프로필과 모든 글을 한 번에 보고 싶다. 인터뷰(deep-interview)와 SPEC 논의로 범위를 확정했다.

### 2.2 조사로 확인한 것

용어 풀이 — **볼트**: 옵시디언이 쓰는 노트 폴더. **frontmatter**: 노트 맨 위 `---` 사이의 속성 목록. **인덱스**: 볼트 노트를 뷰어가 읽기 좋게 한 파일로 모은 목록.

## 4. 검토한 옵션과 기각 근거

| 선택 | 채택 | 기각한 안 | 근거 |
|---|---|---|---|
| 제작자·계정 연결을 어디 저장하나 | 새 파일 `web_viewer/sns_creators.json` (스키마는 벤치마킹 계정과 같게) | `benchmark_accounts.json`에 제작자 121명 추가 | 켜진 벤치마킹 계정은 수집기 3곳이 계정째 수집한다(F24). 제작자를 넣으면 121명을 통째로 긁으러 간다 |
| 자료 본문 상세 조회 | 기존 상세 경로(정수 순번) 재사용, 자료에는 겹치지 않는 순번 부여 | 자료 전용 새 경로 | 뷰어의 상세 캐시·펼치기 코드를 그대로 쓴다. 순번은 적재 단위 핸들이고 영구 식별자가 아니다(F26) |

### W1 — 볼트 정리와 승격 (`90_자료수집`)

모든 승격은 **capture 스킬을 명시 호출**해 **prepared-md 모드**로 한다(F27) — 본문을 재요약하지 않아 팩트체크·적용방안 층이 보존된다. 볼트 안 `.md` 이동은 `node ~/.claude/scripts/obsidian-fileops.mjs`로, 삭제는 `C:/Users/ahnbu/scripts/safe-trash.ps1`(휴지통, 복구 가능)로 한다.

**prepared-md 스크립트의 입력 조건** (`~/.claude/skills/capture/scripts/import-prepared-markdown.mjs`, 코드 확인) — ① 입력 파일 frontmatter에 `title`과 `source_url`(또는 `source`)이 **반드시** 있어야 한다(128-135행). 대상 대부분은 frontmatter 없이 `# 제목`으로 시작한다. ② 입력 파일을 **이동**시킨다(`fs.rename`, 163행). 그래서 원본을 직접 넘기지 않는다 — 원본을 볼트 `_temp/promote/`에 **복사**하고, 복사본 맨 위에 `title`(원본 첫 `#` 제목)·`source_url`(원본 본문의 원문 URL) frontmatter만 붙여 그 복사본을 넘긴다. 호출: `node import-prepared-markdown.mjs --vault C:/Users/ahnbu/cowork/90_자료수집 --creator <제작자 표시명> --file <복사본>`. 값은 파일마다 다르므로 먼저 대응표 `_temp/promote/promote_map.json`(`[{원본 경로, 복사본 경로, title, source_url, 제작자}]`)을 만든다 — `title`·`source_url`은 스크립트가 원본에서 뽑고, 제작자는 SPEC 부록 A-2의 제작자 열(스레드 핸들)을 볼트 `_제작자별_상세/`의 기존 프로필 파일명과 대조해 정한다(없으면 핸들 그대로 — capture가 신규 프로필을 만든다). 그 표를 한 행씩 읽어 위 명령에 대입한다. 원문 URL을 본문에서 찾지 못한 파일은 승격하지 않고 원래 자리에 두며 그 사실을 §9에 적는다. 이 방식이면 `yt-summary-save/` 원본은 건드려지지 않는다.

- 겹침 노트의 `source_url`로 검색하면 SNS 카드 1장만 나온다(이중 노출 0).
- 자료 카드에 별표·메모를 남기고 `npm run restart` 후에도 유지된다.
- 볼트 노트 제목 한 글자를 고치면 60초 안에 `/api/posts` 응답과 ETag가 바뀐다.

- `node utils/query-sns.mjs`로 자료가 조회된다.
- 회귀: 벤치마킹 표식·사용자 메타 건수·통합본 건수가 W0과 같고, `verify_creator_card_headless.mjs`가 W0과 같은 결과다.
