판정 기준: 기계 검증(done-check)이 불가능한 육안 검증 항목이 다수 포함되어 있으며, 검증 스크립트의 실행 환경(기본 서버 포트)과 임시 계정 파일 분리 계획이 충돌하여 계획대로 실행 시 검증 스크립트가 운영 파일을 오염시키는 문제를 막지 못합니다.

## Blocking Issues
1. 육안 검증 의존으로 인한 done-check 판정 불가
- 근거: §3 W1 완료 기준 "실제 화면 캡처", W5 완료 기준 "4종에서 두 줄이 구분돼 보인다", §4 검증 공통 규칙 "실제 화면에서 대상 게시글 확인"
- 사유: done-check는 로그와 종료코드 등 명시적 증거를 바탕으로 사람의 눈 없이 자동 판정해야 합니다. 브라우저 화면을 사람 눈으로 확인해야 하는 기준은 자동 실행 및 검증을 막습니다. Playwright 등을 통한 DOM 요소 검증(CSS 클래스 존재 여부, `boundingBox()` 좌표 실측 등)이나 데이터 무결성 검증 스크립트로 대체하여 종료코드(exit code)로 판정할 수 있도록 수정해야 합니다.

2. 검증 환경(W2)과 서버 실행 방식(공통 규칙)의 충돌로 인한 테스트 격리 실패
- 근거: §3 W2 채택안 "서버가 환경변수로 그것을 본다" vs §4 검증 공통 규칙 "npm run restart로 5000번 재시작한 뒤 검증한다"
- 사유: W2에서 서버 코드를 수정해 임시 경로를 환경변수로 받도록 하더라도, 검증 시 공통 규칙대로 `npm run restart`를 통해 평범하게 서버를 띄우면 테스트용 환경변수가 주입되지 않아 여전히 운영 파일(`benchmark_accounts.json`)을 참조하게 됩니다. 이 상태로 테스트 스크립트(`verify_*.mjs`)를 돌리면 운영 파일 오염이 그대로 재현되므로 W2의 목표 달성에 실패합니다. 테스트용 환경변수를 주입해 별도의 테스트 서버를 띄우는 과정(예: 테스트 스크립트 내부에서 서버를 spawn하거나 전용 테스트 런처 사용)을 명시해야 합니다.
