## 2. 문제

### 2.1 원인 — 번역 자막 요청이 429로 차단된다

`download_transcript()`(`youtube_scrap.py:390-402`)는 모든 영상에 `--sub-langs ko-orig,ko` 만 요청한다.

- `ko-orig` = **원본이 한국어인** 영상의 자동자막
- `ko` = 원본이 무슨 언어든 **한국어로 자동 번역한** 자막

유튜브는 번역 자막 요청을 강하게 제한한다. 그래서 영어 원본 영상은 `ko-orig` 가 없어 `ko`(번역)로 넘어가고, 거기서 `HTTP 429 Too Many Requests` 를 맞는다. 코드는 이 거부를 `no_subtitle`(자막 없음)로 기록했다.

실측 대조(2026-08-27, 각 요청 사이 12초 이상 간격):

| # | 요청 | 대상 | 결과 |
| --- | --- | --- | --- |
| A | `ko-orig,ko`(현행) | Eric Tech · Nate Herk | **429 실패** |
| B | `ko-orig,ko,en-orig,en` | Eric Tech | **429 실패** — `ko` 에서 먼저 막혀 `en` 까지 못 감 |
| C | `en-orig` | Eric Tech · Nate Herk | **성공** (180KB · 175KB) |
| D | `en` (원본이 영어라 번역 아님) | Eric Tech | **성공** |
| E | `.*-orig` | 영어 영상 2건 + 한국어 영상 1건 | **전부 성공** (각각 `en-orig`, `ko-orig` 획득) |
| F | `.*-orig` → 실패 시 `ko,en` | YTN(`-orig` 없음, 수동 en 자막) | 1차 실패 → **2차 성공** (37KB) |

**B가 핵심이다.** 언어를 나열만 해서는 안 되고, 실패 시 별도 호출로 넘어가는 2단계여야 한다.

### 2.2 주석과 구현의 불일치

`youtube_scrap.py:395-396` 주석은 이렇게 적혀 있다.

> ko-orig 하나만 요청한다. (…) 한국어가 없으면 아래에서 en 으로 한 번 더 시도한다.

**그 재시도 코드가 없다.** 주석만 남고 구현이 빠진 상태다.

### 2.3 파급

- 요약 대기가 295건이 아니라 **319건**이다(295 + 24).
- 앞으로 저장하는 영어권 영상은 **전부 같은 경로로 유실된다.** 최근 저장 목록에 영어권 AI 채널 비중이 높아 재발률이 높다.
- `no_subtitle` 이 "자막 없음"과 "멤버 전용"과 "429 거부"를 한 값으로 뭉뚱그려, 화면에서 요약이 없는 이유를 구분할 수 없다.

### 2.4 사용자 질문에 대한 답

별도 목록 관리는 **지금 하면 해롭다.** 자막이 멀쩡한 24건에 "영구 제외" 딱지를 붙여 묻어버리게 된다. 목록 분리는 24건을 회수한 뒤 남는 11건에 대해서만 의미가 있다.

### 3.2 S1 상세 — 2단계 폴백

```
1차: --sub-langs ".*-orig"   원본 자막만 요청. 번역 요청을 아예 하지 않아 429가 원천 차단된다.
                             한국어 영상은 ko-orig, 영어 영상은 en-orig, 그 외 언어도 원본을 받는다.
2차: --sub-langs "ko,en"     1차가 빈손일 때만. 수동 자막이 있는 예외 케이스를 잡는다(YTN).
```

원본이 제3 언어(일본어 등)면 그 언어 자막을 받는다. 요약은 Gemini가 하므로 한국어 산출에 지장이 없다.

### 3.3 S2 상세 — 멤버 전용 감지

yt-dlp 출력에 두 형태로 나타난다.

```
ERROR: [youtube] AmePj1SI6Z4: Join this channel to get access to members-only content like this video, and other exclusive perks.
ERROR: [youtube] 3fvglK7Czjg: This video is available to this channel's members on level: 서포터즈 (or any higher level). Join this channel to get access to members-only content and other exclusive perks.
```

두 줄 모두 2026-08-27 실측 출력이다. 공통 토큰은 `members`. `members-only` 만 매칭하면 두 번째 형태를 놓친다.

### 3.4 S4 재시도 정책 — 근거 정정

착수 보고에서 "멤버 전용 5건을 매 실행 재질의하는 것이 낭비"라고 적었으나 **실측 결과 그 근거는 과장이었다.**

| 케이스 | 1건 소요 | 비고 |
| --- | --- | --- |
| 멤버 전용 | **2.3초** | 즉시 ERROR |
| 자막 없음(1차) | **4.3초** | |
| 자막 없음(2차) | **4.0초** | |

기존 문서의 "한 건당 최대 3분"은 타임아웃 상한이지 실제 소요가 아니다. 11건 전부를 매번 재시도해도 병렬 처리에서 10초 미만이다.

**그러므로 상태 분리의 근거는 비용 절감이 아니라 진단 가능성이다.** 요약이 없는 이유가 "결제하면 되는 것", "업로더가 자막을 켜면 되는 것", "우리 버그"로 갈리는데 지금은 전부 `no_subtitle` 한 값이다. 구현 비용이 조건문 하나 수준이라 진단 가치만으로 정당화된다.

정책:

| 상태 | 재시도 | 근거 |
| --- | --- | --- |
| `members_only` | **안 함** | 멤버십 결제 전에는 원리적으로 불가 |
| `no_subtitle` | **함** | 업로더가 나중에 자막을 켤 수 있음. 6건·4초라 비용 무시 |
| `failed` / `blocked` | **함** | 일시 장애 |
