### W3 — `scrap_sns_server.py` 인증 신호만 벤치마킹까지 인정한다

**🔴 [`_canonical_auth_platform`](scrap_sns_server.py:624) 자체를 고치지 않는다.** 그 함수는 [:640](scrap_sns_server.py:640)의 `platform_results` 정규화 루프도 함께 쓴다. 거기에 `bench_linkedin` → `linkedin` 매핑을 넣으면 [:644](scrap_sns_server.py:644) `platform_results[platform] = raw_result`에서 벤치마킹 결과와 저장글 결과가 **같은 키를 두고 서로 덮어써** 한쪽이 조용히 사라진다. 이 절이 피하려는 결과가 바로 그것이다.

**대신 인증 전용 헬퍼를 새로 만든다.**

| 무엇 | 어떻게 |
|---|---|
| 신규 헬퍼 | `_canonical_auth_required_platform(value)` — 값이 `bench_`로 시작하면 그 접두사를 떼고, 그 결과를 기존 `_canonical_auth_platform()`에 넘긴다. 매핑 규칙 자체는 한 곳에 그대로 둔다 |
| 적용 위치 ① | [:650-652](scrap_sns_server.py:650) — `total_scrap`이 보낸 원본 `auth_required` 리스트를 담는 지점 |
| 적용 위치 ② | [:677-683](scrap_sns_server.py:677) — 최종 `normalized_auth_required` 생성 루프 |
| **건드리지 않는 곳** | [:639-647](scrap_sns_server.py:639) `platform_results` 루프. **여기는 기존 `_canonical_auth_platform`을 그대로 쓴다** |

**왜 이 두 곳이면 충분한가:** 벤치마킹 인증 신호가 서버에 들어오는 통로는 원본 `auth_required` 리스트뿐이다. `platform_results`에서 파생되는 경로([:659-673](scrap_sns_server.py:659))는 [:641-642](scrap_sns_server.py:641)에서 벤치마킹 항목이 이미 버려진 뒤라 도달하지 않는다.

**프런트는 안 고친다:** 서버가 `linkedin`으로 정규화해 보내므로 `web_viewer/script.js`의 `normalizeAuthPlatform`이 그대로 받는다.

**의도한 결과:** 인증 만료는 두 경로가 같은 세션 파일을 보므로 뭉쳐서 안내해도 정확하다. 반면 일반 수집 실패(`failed`)는 원인이 달라 뭉치면 안 되고, 위 설계에서 그 표시는 **현행 그대로 유지된다.**

**회귀 확인:** `tests/integration/test_run_scrap_stats.py`가 `platform_results` 응답 모양을 대조한다. 이 변경으로 그 기대값이 바뀌지 않아야 한다(바뀌면 `platform_results`를 건드린 것이다).

## 5. 검토하고 기각한 안

| 안 | 기각 사유 |
|---|---|
| **A. 정본 정책을 그대로 채택 (화면 밖 headed)** | 정본 스스로 "좌표만으로는 안 숨는다"고 적어놨다. 실제로 숨기려면 `psutil` 신규 의존 + persistent 프로필 전환이 필요하고, 그러면 인증 저장 방식(`storage_state`)까지 갈아엎어야 한다. **비용이 크고, 그러고도 headless보다 나은지가 미측정이다** |
| **B. `headless=True`를 이 파일에만 적어 넣는다** | 동작은 된다. 그러나 실측 지식이 파일 주석에 갇힌다 — `twitter_scrap.py`에서 이미 한 번 일어난 일이다(P5) |
| **C. 정본 값을 레포로 복사하고 주석으로 「정본과 맞춰라」 메모** | **이 하네스가 안 쓰는 방식이다.** 실제 도는 장치는 ①계약 줄 + 교차 실행 대조(`browser_launch` py↔mjs) ②밀어내기 동기화 + 테스트(`sync_auth_runtime.ps1`, 사본 3벌 해시 동일 확인) ③아예 사본을 안 만듦(`x_auth_scrape.py`) 셋이다. 메모는 갈려도 아무도 모른다 |
| **D. 값 복사 + 계약 대조 테스트를 레포에 신설** | 성립하는 차선안. 레포 자립을 지킨다. 그러나 이 레포는 **이미** `~/.config/auth/` 없이는 LinkedIn·Threads 수집이 안 되고 CI도 없어(`.github/workflows` 없음), 지킬 자립이 실질적으로 없다. 테스트 30줄이 순비용 |
| **E. 비로그인 공개 경로로 전환** | 실측 기각. 비로그인 활동목록은 HTTP 999 차단, 카드 0개. `utils/linkedin_metrics.py`의 비로그인 경로는 **글 주소를 이미 알 때만** 쓴다 |
| **F. 벤치마킹을 저장글 수집과 한 브라우저로 합쳐 wave를 되돌린다** | 방향은 옳으나 지금 불가. `linkedin_scrap_by_user.py`가 **모듈 최상단에서 `argparse.parse_args()`를 실행**해([:16-22](linkedin_scrap_by_user.py:16)) import 자체가 안 된다. 654줄 재구조화가 선행이다. → **2단계로 분리** |
