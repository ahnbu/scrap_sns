# SNS 벤치마킹 계정 수집·관리 수행계획

## 이 문서를 읽는 법

SPEC은 **무엇을 만들지**를 정했고, 이 문서는 **어떤 순서로 만들고 무엇으로 다 됐다고 판정할지**를 정한다.
SPEC과 충돌하면 SPEC이 우선하되, 검수(2026-09-06)로 SPEC에 추가된 D12~D16은 이 문서의 순서를 그대로 따른다.

만들기는 P0~P6, 검수는 P7(화면 디자인)·P8(사용자 시나리오)이다. **P7·P8은 만든 뒤에 수행하는 단계이며, 통과하지 못하면 착수 완료가 아니다.**

`scrap_sns`에는 지금 **내가 저장(북마크)한 글 2,685건만** 들어온다. 저장 여부가 「그 글이 좋았나」에 좌우되므로 잘 된 글만 모이고, 망한 글이 데이터에 아예 없다. 벤치마킹할 계정을 지정해 그 계정 글을 통째로 긁으면 이 편향이 사라진다.

## 해결 — 8단계 (만들기 P0~P6 · 검수 P7~P8)

**순서를 바꿨다.** SPEC D7은 「API → 동기화 → 화면 → 수집 → 표시」였으나, **스키마와 매칭 키가 화면보다 먼저다.** 나중에 소급할 수 없기 때문이다(C1·C4).

각 단계는 **다음 단계로 넘어가기 전에 그 단계의 완료 판정을 통과**해야 한다.

**P7·P8은 만드는 단계가 아니라 검수 단계다.** P0~P6의 완료 판정은 조각이 도는지만 본다 — 화면이 기존과 따로 노는 문제(P7)와 흐름 전체가 쓸모 있는지(P8)는 거기서 안 잡힌다. **P8을 통과하지 못하면 착수 완료가 아니다.**

### P1. 저장 파일 + 서버 API 3개

> **API가 3개인 이유** — 주소 검증(P4)은 브라우저에서 직접 못 한다. `YOUTUBE_API_KEY`는 `~/.env`에 있고 `youtube_scrap.py:943`이 서버측에서만 읽는다. **키를 프런트로 내보내면 안 되므로 서버가 대신 조회하는 라우트가 있어야 한다.** 이게 없으면 P4가 설계상 실행 불가다.

| 대상 | 작업 |
|---|---|

| `_docs/architecture.md` | 신규 라우트 **3개** 문서화 |

### P7. UI 디자인 검수 — **기존 화면과 어긋나지 않는지 별도로 본다**

**왜 별도 단계인가** — P3·P6의 완료 판정은 *"기능이 되는가"*만 본다. 화면이 **기존과 따로 노는 것**은 기능 테스트를 전부 통과해도 남는다. 이 레포의 뷰어는 색·모서리·배지·확인창이 한 벌로 굳어 있어서, 새 탭 하나가 그 결을 깨면 바로 티가 난다.

**언제** — P3 직후 1회(계정 관리 화면), P6 직후 1회(카드·필터 반영). 두 번 다 캡처를 남긴다.

#### 검수 방법 — 기계 판정과 사람 판정을 나눈다

**둘을 섞으면 done-check가 판정할 수 없다.** 기계로 잴 수 있는 것은 종료코드로 닫고, 눈이 필요한 것은 사람에게 넘기고 멈춘다.

**(가) 기계 판정** — `scripts/verify_benchmark_ui_design.mjs`(신규, `_shared/hidden-browser-verify-runner.mjs`, **창을 띄우지 않는다**). 뷰포트 4종 `1440×900` · `1280×800` · `768×1024` · **`430×932`**에서 아래를 재고, 전부 통과 시 exit 0, 하나라도 실패 시 항목명 출력 후 exit 1.

| 검사 | 기계 판정 방법 |
|---|---|
| 탭 바가 잘리지 않는다 | 각 뷰포트에서 `scrollWidth <= clientWidth` **또는** `overflow-x`가 `auto`/`scroll`이라 스크롤 가능 |
| 팔레트를 벗어나지 않는다 | 신규 탭 하위 요소의 `color`·`background-color`·`border-color`·`border-radius`·`font-size` 실측값이 기존 4개 탭에서 수집한 값 집합에 포함 |
| 새 위젯이 없다 | 신규 탭 안에 `input[type=range]`·`[role=switch]`·`[draggable=true]`·신규 `[role=dialog]`가 **0개** |
| 모달이 화면을 안 넘는다 | 계정 25개 렌더 상태에서 패널 높이 `<= 0.85 * innerHeight` |
| 배지 3개 카드의 줄이 안 깨진다 | 그 카드의 푸터 `scrollWidth <= clientWidth` |

**(나) 사람 판정** — 밀도·위계·문구는 기계가 못 잰다. 스크립트가 아래를 캡처해 `_docs/evidence/20260906_01/design/`에 저장하고, **AI는 여기서 멈춰 사용자 승인을 받는다.** 승인 없이 다음 단계로 넘어가지 않는다.

### P8. 사용자 시나리오 점검 — **내가 실제로 쓰는 순서대로 해본다**

**왜 필요한가** — 단계별 완료 판정은 조각을 본다. *"설정에서 켜고 → 수집하고 → 검색해서 소재를 건진다"*는 흐름 전체가 한 번도 이어서 검증되지 않는다. SPEC의 목적(§목적)이 성립하는지는 **이 흐름에서만** 드러난다.

**언제** — P6 완료 후.

**어떻게 판정하나** — 17개를 두 갈래로 나눈다. **섞으면 done-check가 증거로 판정할 수 없다.**

### P9. 메인 화면 진입점 — **사용자 지적으로 추가 (2026-09-06)**

**빠뜨린 것**: A2(「벤치마킹은 꺼두고 시작」)를 구현하면서 **토글을 Settings → 표시 탭 안에만 뒀다.** 그리고 켠 뒤에 무엇을 하는지를 만들지 않았다.

> 사용자: *"메인 뷰어에서 벤치마킹을 보는 토글이 바로 보여야 하는 거 아닌가??? 게다가 벤치마킹 토글 on이 되었을때에도 벤치마킹 전용 서브 기능들을 전혀 볼 수 없는데... 도대체 뭘 어떻게 쓰라는 건가?"*

지적이 맞다. **A2는 「기본 화면을 남의 글로 덮지 마라」였지 「진입점을 설정에 묻어라」가 아니었다.** 그리고 SPEC 목적 4개 중 「새 소재 픽업」·「형식·훅 학습」·「선점 역판정」 셋은 **벤치마킹 글만 따로, 계정별로** 봐야 성립하는데 그 수단이 하나도 없었다.

#### 무엇을 만들었나 — 기존 `MY` 버튼의 대칭

| 조작 | 위치 | 무엇 |
|---|---|---|
| **「벤치마킹」 칩** | 상단 필터 줄, `MY` 옆 | **남의 계정 글만 보기.** `MY`(내 글만)의 반대편이라 새 개념이 아니다 |
| **계정 칩 줄** | 태그 칩 줄과 같은 자리 | 켜진 계정 + 건수(`전체 49 · 빌더 조쉬 5 · 우석지니 5 …`). 누르면 그 계정만 |
| **카드 배지 클릭** | 카드 푸터 | 배지에 계정명이 뜨고, 누르면 그 계정만 보기. 저자명 클릭 선례와 같은 결 |
| **표시 탭 토글** | Settings → 표시 | **역할을 갈랐다** — 이건 「내 저장글과 섞어 보기」(소재 검증용)다. 「남의 글만」은 상단 칩이다 |

**상태가 3가지로 갈린다**

| 무엇을 하려나 | 조작 |
|---|---|
| 평소 — 내 저장글만 | 기본 (둘 다 꺼짐) |
| **소재 검증** — 이미 풀린 소재인가 | 표시 탭 토글 켬 → 한 목록에서 함께 검색 |
| **형식 학습** — 이 계정은 뭐가 잘 됐나 | 상단 「벤치마킹」 칩 → 계정 고르기 → 성과순 정렬 |

**상호 배타** — `MY`와 「벤치마킹」은 교집합이 0이라 둘 다 켜면 항상 빈 화면이 된다. 한쪽을 켜면 다른 쪽이 꺼진다. 벤치마킹을 켤 때 플랫폼·태그·저자 필터도 푼다(`MY`의 `relaxFiltersForOwnPosts()`와 같은 이유).

**빈 상태** — 켠 계정이 없으면 *"켜둔 벤치마킹 계정이 없습니다. 설정 → 벤치마킹에서 켜세요."*, 계정은 켰는데 수집분이 없으면 *"수집을 한 번 돌리세요."*
